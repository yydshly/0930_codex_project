# 内容与编号约定

## 编号与目录

子项目目录格式为 `projects/001-project-slug/`，编号至少补齐三位，超过 999 后继续自然增长。`slug` 使用小写英文字母、数字及连字符。

编号按加入顺序分配，首页按编号升序排列。编号不因研究完成、暂停或改名而变化；不删除已登记记录、不复用编号，停止研究时设置为 `已归档`。模板不参与编号，也不计为研究项目。

## 统一清单

`projects.json` 是首页索引的数据来源。不要直接编辑主 README 中两组生成标记之间的内容；标记之外的简介与说明可以自由修改。

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一正整数，固定研究编号 |
| `slug` | 唯一的目录短名 |
| `name` | 项目显示名称 |
| `repo` | 上游 GitHub 仓库 HTTPS 地址 |
| `summary` | 首页展示的一句话摘要 |
| `status` | `待研究` / `研究中` / `已完成` / `已归档` |
| `demo` | 已验证的 HTTPS 演示地址；没有则为空字符串 |
| `cover` | 相对子项目目录的图片路径，如 `assets/overview.png`；没有则为空字符串 |

新增研究使用 `python scripts/projects.py add`；修改清单后使用 `render`，提交前运行 `check`。CI 会检查重复编号、目录、链接格式、封面文件及首页生成内容。检查不访问上游网站，也不证明演示在线可用。

摘要建议使用“能力：……；原理：……；场景：……；价值：……；扩展：……”的单行纯文本，也可按项目使用“定位、内容、用途、产物、运行、平台”等标签。首页生成器会将标签加粗：项目索引表内按模块换行，项目预览中每个模块显示为独立列表项。普通未分模块的摘要仍按原文显示，无需在清单中写 Markdown 或 HTML。

## 每个子项目的内容

- `README.md`：项目简介、上游来源、运行方法、代表图片、结论与入口。
- `notes/`：深入研究、实验过程、问题排查和版本记录。
- `assets/`：截图、架构图和演示动图；建议使用压缩后的 PNG、JPEG、WebP、GIF 或 SVG。
- `web/`：可选的 Web 演示及运行说明；建立研究时只预留位置。

首页封面应有代表性；详细截图放在子项目 README，使用有意义的替代文字并配简短说明。避免将录屏、大型原始素材、依赖目录、下载的上游完整源码或构建产物放入 Git。

不同子项目可以使用不同技术栈，各自管理依赖和运行步骤。需要引入上游代码时，先确认版本与许可，再决定使用 Fork、依赖包或单独克隆；不默认使用 Git submodule。
