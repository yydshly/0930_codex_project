## 01 · 空间作品集生成器

[原作](https://x.com/cambreedesigns/status/2104999693113766152)：作者自述三次提示制作作品集；原片可见服装挂架式陈列和作品展示。

需要保留的能力：把作品做成可探索的物件陈列，而不是只把图片排进卡片。

原作披露的技术：作者提到 Opus；网页内部渲染框架未披露。

我们的实现：原创成果物件陈列、可选择作品和详情、内容配置与 HTML 交付。 技术：CSS perspective / transform 物件陈列、悬停与拖动；同一内容配置驱动详情和独立 HTML。

可复用思路：内容配置 → CSS 透视陈列 → 悬停/拖动/详情 → 同配置导出网站。

与我们相关的产品：空间作品集与案例站生成器。将项目素材变成有记忆点的空间作品集，适用于我们的研究集与客户案例站。

实际核对点：选中具体成果时，陈列、详情和导出的内容一致。

差距与范围：借鉴陈列方式与浏览效果；没有复现“三次提示自动生成”的模型调用。

## 02 · 程序化研究街区 RPG

原作披露的技术：代码生成纹理、场景与声音是作者自述；未取得原作源码。

我们的实现：程序化研究街区、第一人称探索、分支证据任务、终端式记录和合成提示音。 技术：本地 Three.js、程序化几何与材质、Web Audio、共用任务状态。

可复用思路：程序街区 + 第一人称镜头 + 对话/证据状态机 + 合成音效。场景和终端读取同一任务状态。

与我们相关的产品：三维互动任务与剧情训练工具。把 SOP、设备巡检与知识核对放进可探索的训练场景。

实际核对点：镜头实际移动；选错分支会反馈；任务记录和提交结果一致。

差距与范围：保留三维探索与任务整合；未复现 Fallout 资产、V.A.T.S. 或完整战斗系统。

## 03 · 研究观点叙事片

[原作](https://x.com/sevdeawesome/status/2104985610012504181)：原片约 5 分 16 秒。已观察 10 秒线框工具、35 秒论文页、180 秒线框球体、250 秒增长曲线等镜头，分别承担观点说明与比较。

需要保留的能力：观点有推进关系，画面、文字与镜头随论证变化，最后能交付一段动态视频。

原作披露的技术：制作软件、模型与渲染流程未披露，不能由画面反推。

我们的实现：围绕研究成果的观点镜头序列、可编辑脚本、时间线和真实动态视频导出。 技术：原创 Canvas 镜头编排、统一时间轴、浏览器视频录制。

可复用思路：每个观点对应镜头函数；同一时间轴支持播放、寻址、脚本与连续视频导出。

与我们相关的产品：观点与课程叙事编辑器。把我们的研究结论、课程观点与复杂概念做成可编辑叙事片。

实际核对点：拖动时间线能恢复对应镜头；视频导出包含真实的连续画面。

差距与范围：短篇原创论证与代码动画；不等于原片全长、旁白或原作者制作技术。

## 06 · 角色钢琴音乐动画

[原作](https://x.com/kevin_t_ngo/status/2105304249060274631)：作者明确写到 Python 编写钢琴音乐、Python 创建三维动画、Blender 渲染；原片可见角色与黑猫在实体钢琴上演奏。

需要保留的能力：同一份乐谱同时生成音乐、角色动作和琴键关键帧，交付音画同步的三维动画。

原作披露的技术：Python → 三维动画脚本 → Blender，是作者明确披露的流程。

我们的实现：原创实体钢琴、研究机器人和猫的演奏场景；共用乐谱驱动音频、琴键与角色，并交付 Python / Blender 脚本。 技术：网页用 Three.js + Web Audio 实时预览；Python 标准库写 WAV；bpy 脚本设置三维场景、关键帧和渲染。

可复用思路：把音符写成带时间的事件：Web Audio / Python wave 生成声音，Three.js / bpy 读取同一事件安排弹键与角色动作。

与我们相关的产品：音乐与角色动画配方工具。将音乐、品牌角色与镜头沉淀成可复现的音乐动画配方。

实际核对点：旋律或节奏修改同步改变音频时长、角色动作、琴键与脚本关键帧。

差距与范围：Python 音频已运行；本机没有 Blender，bpy 脚本与渲染流程待在 Blender 内验证。网页画质不等同原作离线渲染。

## 08 · 立体吉祥物触碰沙盒

[原作](https://x.com/AugustCastilIo/status/2105350465001029697)：作者自述第四款游戏。已观察触碰后角色腾空，以及柔软度、声音、重力等设置；样片还有新增与混合入口，完整机制未验证。

需要保留的能力：立体软萌角色的触碰、压缩回弹、跳起和反馈设置本身就是可参考的能力。

原作披露的技术：角色建模、变形与游戏逻辑工具链未知。

我们的实现：原创三维角色触碰沙盒、弹性与重力/声音设置；计分挑战是我们添加的可选扩展。 技术：Three.js MeshPhysicalMaterial 高光材质、射线命中、局部顶点形变、阻尼回弹与重力积分。

可复用思路：触碰命中 → 压缩与回弹 → 重力跳起 → 声音/情绪反馈；参数影响同一角色状态。

与我们相关的产品：互动角色与品牌反馈组件。用角色表达欢迎、提示和品牌情绪，再根据真实业务决定是否需要小游戏任务。

实际核对点：触碰会变形和弹起；柔软度、重力与声音开关影响真实反馈；附加挑战不被写成原作玩法。

差距与范围：局部顶点与弹簧近似，未实现完整软体模拟或原作的全部混合/黏液功能；自创连击是我们的扩展。

## 09 · 可漫游的热带研究营地

[原作](https://x.com/maxt3chno/status/2105216139647127750)：作者明确披露 Three.js、水草地形、天气日夜，以及代码与 Meshy 模型混合制作。

实际核对点：走到近处查看对象；改天气和时刻后，天空、光线、水面和交互保持一致。

差距与范围：没有复现作者全部道具与游戏机制，也未调用 Meshy；折射只捕获当前相机，焦散仍为图形近似，自然资产仍有差距。八块扫描主岸石来自 [Poly Haven / Rico Cilliers](https://polyhaven.com/a/boulder_01)，CC0；扩展指标不代表校准的现实模型。

## 10 · 三维车球物理挑战

[原作](https://x.com/BlendiByl/status/2104800823620632641)：作者提供浏览器车球同人游戏并强调物理；原片可见立体球场、跟随视角和 Boost。

需要保留的能力：立体车球场、追车或球相机、加速、惯性与真实碰撞共同决定操控手感。

原作披露的技术：具体物理引擎未知；不能由效果推定使用某个引擎。

实际核对点：加速改变速度；相机随车辆或球变化；碰撞后球发生运动并能进球。

差距与范围：单人简化物理；没有原作的全部空中技巧、完整仿真或多人比赛。
