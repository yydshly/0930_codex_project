记录日期：2026-10-02。范围按 `web/demo/index.html` 与 `web/demo/app.js` 的当前实现整理；功能、视觉和设备结果需结合独立浏览器检查记录。这里没有把作者样片视为我们运行了相同工具链。

[主站实际演示](http://127.0.0.1:8975/#demo) · [独立演示](http://127.0.0.1:8975/demo/) · [操作与运行说明](../web/demo/README.md)

## 为什么选择这个任务

我们已有作品研究、代码动画和三维交互成果。将“交互产品展厅”收敛为“为研究工作台选一盏灯”，能够把看懂产品、调整参数、保留基准、比较差异和交给团队讨论串成一次完整任务。结果是可操作概念原型与可检查文件，后续可用真实用户验证理解和选型记录是否准确。

该场景采用项目 011 的原创 ARC 概念模型和本地渲染器，不复制原帖作者的产品、游戏或媒体实现。015 新增选型预设、方案 A、五项差异对照、本地保存、自动引导和交付文件。

## 一次完整体验

输入是方案名称、用途和有限的视觉配置。用户可以从工作桌、夜间氛围、展示拍摄三种预设开始，修改配色、哑光或亮面、日光或夜景、室内或简洁背景、画面光感与结构展开。

整体、正面、细节、结构四个视角帮助观察；四个部件入口调用渲染器聚焦并显示说明。这里的部件入口位于画面下方，不是实时跟随模型的覆盖热点。

保存方案 A 后，继续修改的配置就是 B。对照区比较五项：配色、表面、使用氛围、展示环境、视觉亮度。展开比例、自动旋转与观察视角仍在配置文件内，但不计入这五项差异。用户可恢复 A，也可只重置当前配置而保留 A。

自动引导共四步，每五秒换一步，约二十秒结束。它改变当前配置，不会替用户保存 A；操作参数、部件或视角会停止引导。任务进度条记录本次查看、保存、形成差异和下载动作，是操作提示，不是学习或商业效果评分。

## 状态与交付

| 内容 | 当前实现 |
| --- | --- |
| 当前选择 | 配置、方案名称、用途和标准视角；改动后更新画面与本地保存。 |
| 基准 A | 名称、用途、配置、标准视角与保存时间；可与当前选择对照或恢复。 |
| 保存位置 | 当前访问地址下的浏览器 localStorage；不上传，不跨浏览器同步。 |
| JSON | 配置、观察状态、基准 A、五项差异、来源和范围。没有文件导入入口。 |
| Markdown | 用途、当前选择、展开比例、标准视角、与 A 的差异及评审边界。 |
| PNG | 当前 Canvas 的画面；不包含表单、部件文字或对照表。 |

配置和标准视角可恢复；渲染器没有公开任意自由相机角度的恢复 API，因此不会精确恢复拖动后的方向。重新加载或恢复 A 会关闭自动旋转。查看和导出都在本机进行，没有订单、预约或采购接口。

## 实现与复用范围

主站 `#demo` 同源嵌入 `/demo/?embedded=1`；独立 `/demo/` 显示完整页面。主站切换离开演示时通知子页面停止引导和自动旋转，渲染器也会依据可见性控制绘制。

`web/demo/app.js` 负责业务状态与文件；`runtime/product-renderer.js` 和 `scene-materials.js` 来自 011 的原创实现。本地 Three.js r160、许可和三张 WebP 素材随演示保存，避免依赖跨项目的 HTTP 路径、外部 CDN 或云端调用。

生成的室内全景是 LDR 概念素材，木石纹理与参数化几何用于视觉表达。模型没有使用真实制造尺寸、材质样本或照明测量；画面光感 `0–100%` 也不能解释为真实照度。没有价格、库存、支付和订单。

WebGL 不可用时使用二维兼容画面，保留部分配置、结构与交付功能；自由旋转和完整三维材质效果不在二维范围内。需要真实浏览器检查兼容入口、存档与下载，不依据代码存在推定所有设备已经通过。

## 后续该验证什么

- 首次使用者能否说出四个部件的作用，并完成一次有目的的配置比较。
- 保存 A 后修改 B，五项差异是否准确；恢复 A 后配置与标准视角是否一致。
- 选型记录、JSON 和画面是否与导出时的当前状态一致；本地保存不可用时是否仍可下载。
- 三维与二维、窄屏与桌面入口是否可用，画布和控件是否互相遮挡。
- 团队是否能凭记录继续讨论，以及下一套实际产品是否值得模板化。

浏览器检查脚本为 `tooling/verify-demo.mjs`，运行后保存 `notes/demo-verification.json` 与 `assets/qa/our-demo-*.png`。这类工程检查不能证明实物性能、用户理解、采购效果或收费意愿。

下一步应先补真实用户任务，再决定是否加入实物尺寸与测试数据、模型导入、更多模板、团队保存或采购服务。现在已有一个可操作概念原型；八个产品方向仍是待逐项实施和验证的完整产品计划。
