01 / WHO DOES WHAT

一件作品，先分清创作阶段和运行阶段。

人 / 产品规则

确定目标、人群、内容事实、品牌、风格、可用素材与预算；决定什么结果值得接受。

模型 / 创作与修订

提炼内容、构思故事、设计分镜；编写场景代码，或用专门的图像 / 视频模型制作素材；根据反馈修改。

程序 / 执行与交付

加载素材、运行图形与游戏逻辑、推进时间、检查错误、编码并保存文件。规则只有写进程序，才能被强制执行。

制作时需求 → 模型 / 作者 → 代码与素材

模型参与创作，但还要预览、检查和修改。

→
运行或导出时代码＋素材＋时间 / 输入 → 画面

已写好的程序负责执行；游戏还会响应玩家操作。

例如动态字体短片：模型设计字的出现顺序和运动，浏览器执行代码画出每一帧，FFmpeg 编码 MP4。Opus 在这类项目中承担导演和程序员的角色，画面运动可由程序计算出来。

“每帧都是图片”是文件层面的事实。区别在于帧从哪里来：静态图经过平移缩放、代码重新绘制动态场景、视频模型生成连续表演，或已有视频素材。只看最后的 MP4，无法反推出制作路线。

03 / MODEL ≠ SKILL ≠ RENDERER

Skill 把制作方法交给代理，也连接具体工具。

工具名称所处的层次
层次作用我们讨论过的例子
语言 / 编码模型理解、规划、编写代码和修订；不自动替代全部运行环境。原库中的 Opus；本次对话模型编写实际宣传片。
图像 / 视频模型生成图像或连续的视频画面；能力要按具体模型与接口确认。角色参考生图、H3 人物表演。
Skill / 导演代理提供制作步骤、风格规则、分工、工具调用、预算与审查要求；可以附带脚本和资源。makevoid、Lemo、opus-video-skills；Shipvideo 的导演代理。
图形工程 / 组件提供角色绘制、表情、场景、镜头与动效，模型在其上编排或写代码。ClaudeAnimationBase、p5 场景、Three.js / WebGPU。
渲染、合成与编码工具在指定时刻画帧、处理透明度、拼接音画、编码并交付。Chromium / Puppeteer、抠像脚本、FFmpeg。

Skill 本身没有训练出另一个模型。它的价值在于把“怎么做、用什么、什么时候检查”变成可重复的流程。仅复制提示词，无法复制缺失的角色组件、渲染器、模型权限或素材。

更换模型属于适配工作。可以沿用制作思路与本地工具；接口字段、可用分辨率、音频条件、成本和输出行为需要重新核对。原作效果来自整条制作链路，我们的适配不等于原服务原样运行。

04 / SONG → PERFORMANCE → MUSIC VIDEO

从歌曲到视频：声音驱动表演，时间轴连接各层。

  1. 拆歌曲与叙事保留完整歌曲作主音轨；标记段落、歌词与时间，按需提取人声，设计画面事件。
  2. 确定角色和镜头接受统一身份参考，制作姿态与构图关键帧；决定这一镜用分层、完整场景或其他方式。
  3. 制作表演素材给模型参考图、对应音频与表演提示，生成短镜头；检查身份、动作、嘴部与停顿。
  4. 组织场景与图层如采用绿幕，提取人物透明层；把背景、人物、文字与前景放在同一个镜头时间里。
  5. 连接歌曲时间歌曲第 12 秒 → 本次 10–15 秒镜头的第 2 秒 → 24fps 人物素材第 48 帧。
  6. 审查与成片逐镜头检查后拼接整曲，合入连续原歌曲；编码成功与演唱质量分别验收。

口型来自生成的表演画面

原 makevoid 固定源码用 Fal H3 Max 图生视频并传入 target_audio_url。本机试验使用 MiniMax 官方 API 的参考图 / 参考音频字段。音频是模型输入条件；实际嘴部动作存在于返回视频中。

原主线没有再执行一个独立的“Lip Sync”后处理步骤。此前讨论中的“H3 Max Lip Sync”不应当作我们已经拥有的另一个独立模型名称。

同步要分三个层次验收

  • 素材位置：有没有截到正确歌词、贴到歌曲的正确时间。
  • 粗略节奏：发声与停顿时嘴是否合理开合。
  • 音素嘴形：具体发音和可见嘴形是否匹配。

音频上传成功、嘴部能量相关或主音轨相关性，都不能单独证明第三层通过。提示词可以要求同步，无法把要求变成结果保证。

生成成功、合成成功和表演自然是不同结论。API 成功说明拿到了文件；抠像通过说明能分离；时间映射通过说明使用位置正确。还要实际听看脸部、嘴形、动作、边缘与镜头连续性。

原接口与本机请求对照歌曲、片段与帧坐标口型辅助检测及限制
05 / SUBJECT AND PRODUCTION ROUTE

人物主导、场景主导，与绿幕或整体生成分别选择。

创作选择

画面围绕谁组织？

人物主导：围绕歌手的风格、表演与情绪安排世界。场景主导：围绕列车、城市或事件安排人物。也可以围绕歌词、抽象图形或产品机制，不必强行有歌手。

技术选择

镜头如何制作？

分层合成、完整场景生成、视频后做口型、动作 / 3D 驱动、实拍与已有素材剪辑、无人物动效。它们可按镜头混用，主体选择不强制绑定某一种技术。

具体例子：人物坐在火车里

这张已有静态图，把人物和车厢一起构图。要变成自然动态，还需要同时维持：

  • 机位、透视与人物尺寸匹配。
  • 坐姿、臀部与座位、手与桌面的接触。
  • 桌沿、座椅与手臂正确的前后遮挡。
  • 光线、阴影、色彩以及运动的一致性。

把站立近景人物叠到车窗前，只解决背景替换，无法自动得到坐姿和接触关系。当前本机 H3 试验尚未实现这些互动。

分层路线怎样做？

先设计完整构图，再给人物匹配的姿态与机位，准备场景、接触 / 阴影和遮挡层；生成并提取人物表演后按时间合成。层级、文字与背景更便于修改，但复杂互动需要额外设计。

完整场景路线怎样做？

以人物和车厢已经匹配的完整画面作参考，让模型共同生成镜头。姿态、接触和光线可能更统一，仍需检查变形、身份漂移与表演；修改单一元素可能需要重新生成。

makevoid 默认更偏人物主导的分层动效舞台。原作自然感还依赖统一美术、表演素材、分镜、节奏和多轮审查。绿幕是用于提取人物的手段，无法单独解释全部质量。

→
创作与交付分镜 / 动画代码 → 检查 → 帧 → MP4

模型选择表达与节奏；程序画帧并编码。原库主线没有视频生成模型，也不会自动录制网页操作。

动画能表达产品机制和卖点，也可以结合真实界面录屏、截图、生图、视频片段、配音与配乐。这些需要明确素材入口、来源和制作工具，不能把扩展构想当作当前主链已经实现。

如果做成“输入网址即可生成”的产品，应该落实的规则
产品规则模型可以决定程序要落实
输入范围理解已采集的产品信息。先限定公开单页、大小、跳转、超时和可访问来源；处理动态页面与抓取失败。
宣传事实组织有依据的卖点与文案。保存事实来源；数字、引语和功能说明可追溯，缺失信息允许用户补充。
表现范围在允许的版式与动作中编排。固定规格、风格、组件、字体与可用素材，检查文字长度和阅读时长。
执行与成本按预算选择方案、依据反馈修订。任务状态、预算、有限重试、隔离运行环境、恢复与结果保存。
验收与交付查看画面并修正文案、构图与节奏。运行错误、素材加载、帧数、规格与完整解码检查；事实和美感另做审查。

原库控制与产品建议分别看。Shipvideo 已有导演指令、场景检查与渲染工具；部分限制只是提示词，check_scene 也没有实现“通过检查才允许导出”的强制门控。上表是我们要继续落实的产品设计。

07 / CONTROL AND REUSABLE ENGINEERING

能限制的范围，比尺寸、时长和风格更广。

提示词软控制

要求暖色、少文字、固定机位、准确唱词、某种情绪与镜头风格。模型可能偏离，需要实际检查与修订。

程序硬控制

限制输入、可选素材 / 组件、参数类型、时长、预算、任务顺序与运行环境。规则可以拒绝违规请求，但不会自动证明表演自然或文案正确。

两种产品实现方式
方式模型发挥的范围适用目标与代价
自由代码创作编写完整场景，决定大部分视觉表达。探索多样效果；运行隔离、修复和审查负担较大。Shipvideo 原主线接近此方式。
固定组件 / 模板填内容和参数，选择允许的动效组合。重复生产同一品牌或类型，风格更稳定；需要先建设组件与能力边界。
可沉淀 · 内容层

事实、角色与导演规则

输入快照、卖点来源、统一角色 / 品牌、分镜与节奏约定，让创作有可检查的依据。

可沉淀 · 执行层

统一时间与制作模块

素材版本、时间坐标、角色 / 动效组件、提供商适配、渲染、合成、编码和任务恢复。

可沉淀 · 验收层

过程记录与结果复核

错误、关键帧、成本、参数与修改记录；分别检查技术成功、内容准确和主观效果。

同一模型换了参考、素材、导演规则或组件，结果也会变化。原样片经过什么具体修改无法仅从最终视频确认；复制同一提示词不保证复制同一质量。

08 / TWELVE CORRECTIONS

把容易形成的理解，补充到准确的范围。

本次讨论的查漏补缺
容易形成的理解补充后的结论
这些 MV 都是音乐搭静态图片。图片 MV 是一条路线；代码动画和视频模型表演有不同的运动来源。
Opus 直接生成了这些视频画面。在代码路线中，它主要写分镜与代码；浏览器画帧、编码器生成文件。专门的视频模型可以生成连续镜头。
Skill 就是另一个模型。Skill 组织规则、步骤、工具与资源；结果依赖所调用模型、工程和素材。
全部靠提示词控制。参考图、音频、组件、时间映射、参数与执行程序也参与控制；软要求与硬校验分别看。
只有人物主导与场景主导两种实现。它们是创作方向；技术上还有分层、整体、后对口型、动作驱动、实拍剪辑和无人物动效，可混用。
完整 MV 必须先抠绿幕人物。绿幕适用于分层制作；完整场景、实拍与其他路线可以直接保留人物和场景。
传音频就等于嘴型已经同步。音频作为生成条件；歌词位置、节奏和音素嘴形仍要分层验收。
换背景就能让人坐进火车。还需匹配坐姿、机位、接触、遮挡与光线；普通背景叠层没有完成这些关系。
模型唯一决定效果，我们只能选参数。事实、素材、结构、组件、预算和验收也能由产品定义；设计与工程共同影响质量。
有 MiniMax token 或网页积分，就能用任意视频接口。文本额度、网页积分与 API 权限 / 计费要按账户和接口分别确认。本机只有这次五秒 H3 调用的成功证据。
生成文件成功，说明质量达到原作。文件、时间、合成、口型与美感分别检查；五秒试验也不能证明完整歌曲都达到该质量。
演示网页已经是自动生成产品。本页展示本地已有结果；任意 URL 的后台生成、队列、成本与自动交付仍需建设。
