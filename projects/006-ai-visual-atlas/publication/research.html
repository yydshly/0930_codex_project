作者输入：为一家做推理服务的现代创业公司制作现代、流畅且有冲击力的视频。这个样片没有网址输入，用于对照两种入口。

制作原理：AI 编写一个按时间播放的网页，再把它导出为视频

  1. 提取网页信息web_fetch 读取标题、描述、标题层级、主要颜色和字体。输入网址不会自动变成完整网站操作录屏。
  2. 组织短片与编写场景模型写出单份 1920 × 1080 HTML，用 CSS keyframes 或 requestAnimationFrame 绘制文字、图形和运动。
  3. 在多个时刻检查check_scene 检查 JavaScript 错误和画面文字，代理修正场景。能运行还需要检查节奏、可读性和事实准确性。
  4. 虚拟时钟逐帧推进统一控制 Date、定时器、rAF 与 CSS/WAAPI 动画。__seek(t) 把场景推进到指定时间，避免电脑运行速度改变动画结果。
  5. 编码为 MP4无头 Chromium 输出 JPEG 帧；FFmpeg 编码为 H.264 视频。浏览器负责画图，编码器负责把帧变成可播放文件。
  6. 保存与交付按 2026-10-02 固定版本，MP4 保存到会话工作区，前端查询工具事件并取得下载签名。已有示例仍在 Blob 集合中；此前已在本机查看部分副本；公开版提供作者来源入口。

适合做什么

产品发布预告、功能卖点介绍、动态文字宣传片。需要明确主题、信息优先级和品牌风格；生成文案仍需核对。

观看时重点检查

音乐与叙事

副歌是否明显增强画面？换镜头是否踩在节拍或歌词短句上？不同段落是否有变化而非持续重复？完整结尾是否成立？

角色与合成

同一角色跨镜头是否一致？歌唱口型是否跟音节对应？绿幕边缘是否残留？字幕、人物与背景是否互相遮挡？音频随播放存在，不等于口型已对齐。

制作原理：外部生成角色表演，本地代码控制组合与时间

  1. 分析原歌曲本地 Python 分析节拍、能量和段落；按需要调用转写或人声分离。提供歌词能帮助确定唱词时刻，歌曲始终作为主音轨。
  2. 制定完整分镜确定角色、视觉风格、场景、歌词对应动作、起止帧和预算。先制作开头与高潮的试样，减少整首完成后才发现方向不合适的风险。
  3. 生成并固定角色通过 Fal 的图片生成/编辑接口制作角色参考。锁定接受的角色版本，后续场景复用它，减少外貌漂移。
  4. 生成绿幕表演通过图生视频接口制作单角色、固定镜头、平绿幕背景的表演；按片段提供人声音轨。需要实际检查歌唱口型，传入音轨并不保证同步。
  5. 抠像与程序合成Python 处理抠像与音频；p5.js 负责角色摆放、背景、文字、镜头与定时图形。Swift 可追加特效，但这一部分要求 macOS。
  6. 全曲组装与检查FFmpeg 组装所有连续片段，混合音效。检查每个时间段覆盖一次、总帧数正确、音乐不断裂、没有缺失结尾，交付 MP4 与制作记录。

适合做什么

虚拟歌手 MV、角色音乐故事、带动态排版的歌词视频。角色表演与生成素材、程序动画可以组合；它是一条制作流程，效果取决于素材与逐段审查。
