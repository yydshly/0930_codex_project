# 007 · Koi Scene Lab · 庭院效果与实景构造

[在线体验](https://yydshly.github.io/0930_codex_project/projects/007-koi-scene-lab/) · [原理与价值](web/index.html#tech) · [下载引导图](assets/library-value-map-v21.png) · [本轮说明与依据](notes/understanding-v21.md) · [上游源码](https://github.com/souranyp-stack/koi-pond-garden)

这是一个可在浏览器中运行的实时庭院研究项目：先保留 Koi Pond Garden 原作体验，说明水、鱼、手部与生态的计算方法，再把部分原理接入独立庭院，展示这些能力如何用于个人空间。网页有“原作体验”“按图构造”“原理与价值”三个入口。

![原作效果、技术原理、当前能力、个人价值与扩展方向引导图](assets/library-value-map-v21.png)

引导图由实际原作截图与当前庭院画面组合，按“原作效果 → 底层原理 → 当前实现 → 用户价值 → 扩展方向”阅读；它是说明图，不代表任意照片已经自动重建成三维场景。[当前能力图](assets/project-overview-v20.png)与[生成的庭院设计目标](web/assets/courtyard-target.png)分别保留。

- **原作效果与算法：** 实时波浪、倒影与折射、锦鲤游动和追食、骨骼手部、青蛙与乌龟、晴雨秋冬预设以及环境声音。底层使用 Three.js/WebGL、GPU 双缓冲波场与 Gerstner 波、Fresnel 与 Beer–Lambert 光学、Boids 鱼群规则、SDF/Surface Nets 程序建模、骨骼动画、粒子、HDR 后处理和 Web Audio；这些动态主要由图形算法与行为规则驱动。
- **当前可体验能力：** 按生成效果图构造的可探索庭院，动态水面、鱼嘴边吞食与六粒投喂反馈、轻触后警觉惊散与恢复、庭院猫巡游、青蛙/乌龟/蜻蜓观察。另有部分空间参数、JSON 保存、算法 A/B 实验，以及单文件 GLB 导入、两点尺度校准和人工水域标记。
- **对个人用户的意义：** 通过可探索空间保存老家和家庭记忆，用视角与参数预演庭院改造，为家人加入有情境的动物和互动，也可作为作品展示。当前已能体验庭院和相关算法；数字老家、家庭纪念与实物交付的价值仍需用具体用户和场景验证。
- **可扩展方向与边界：** 未来可发展照片辅助参数建模、乡村建筑构件、家庭共同校正、数字纪念场景、缩尺摆件及数字到实物交付。单张照片缺少背面、遮挡和精确尺寸，需要补充素材、已知长度与人工校正。照片自动重建、可制造模型导出、实物生产和图片/模型/实物一致性验收尚未接入；当前庭院按设计估值构造，未做现场测绘，照片级外观与真实设备性能仍未完成验收。

当前说明为 v21：网页整理八项效果与技术对应、原作和当前实现的区别，以及模型的六层可复用能力。278项自动检查和10项网页阅读、下载检查通过，属于此前限定范围的本地验证，详情见[v21汇总](notes/v21-validation-summary.json)。本轮已发布到 GitHub Pages，35个线上入口与资源的HTTP和SHA-256核对通过，12项公网阅读/下载检查通过。详情见[发布验收](notes/publication-validation-20261008.json)。

## 按图构造

用户指定“先生成一个图片效果，再按效果实现”。本次用内置 image_gen 制作 [固定视觉目标](web/assets/courtyard-target.png) 和石材、砾石、木材与陶瓦四张贴图。来源与提示词见 [生成记录](notes/generated-assets.json)。

按图构造白墙灰瓦房屋、右侧建筑翼与木平台、中央鱼池、后方低桥、左侧枫树与瀑布、前景石板与石灯。参考图是构图对照；空间由独立几何、材质和动态渲染构成。

- 拖动、缩放，参考 / 俯瞰 / 池边 / 鱼群观察 / 平台视角，自动漫游；导入模型后可查看模型全貌。
- 轻点水面产生 GPU 涟漪并保留投喂；点击画布获焦后用E投喂、G轻抚、V清洁画面、空格暂停/继续。真正拖动或缩放退出投喂/抚摸；“查看手部细节”保留旋转观察。
- “效果与技术原理”面板提供九类效果说明、运行数据和演示按钮；可直接观察鱼群、鱼身、惊散、水面、投喂、动物、光照、渲染开销与真实模型尺寸校准。
- 青蛙跳跃、乌龟入水与返回、三只蜻蜓飞行/悬停/停栖，独立观察镜头。
- 暂停动态，流水声与动作短音效，保存实际三维画布 PNG。
- 下午 / 黄昏 / 雨后布光；日照、曝光、清澈度、风与鱼数量。
- 池塘尺度、平台深度、建筑高度，水面网格，参数 JSON 导入导出。
- 参考图透明叠加，查看和下载原始图。
- 导入单文件 GLB，选取两个表面端点并按已知三维直线长度校准，再标记水域、水位、水深、障碍与投喂点；支持校准与绑定 JSON 复用。
- 算法实验台：规则开关、权重、实际方向向量、三球碰撞、水面高度/法线与固定起点 A/B 对照。

设计图为 AI 生成，布局尺寸按设计估计。当前庭院不是某真实地点的测绘结果。真实精度需要照片、已知长度或扫描数据。程序化几何和材质有实时渲染近似，图像生成质量与实时三维画面质量应分别验收。

## 运行与修改

运行资源均在 web/，预览无需安装：

```powershell
python -m http.server 8947 --bind 127.0.0.1 --directory projects/007-koi-scene-lab/web
```

访问 http://127.0.0.1:8947/ 。#original 为原作，#scene 为构造，#tech 为技术。ES modules 请通过 HTTP 加载。

修改后打包：

```powershell
cd projects/007-koi-scene-lab/tooling
npm ci --no-audit --no-fund
npm run build
npm test
```

依赖固定为 Three.js 0.160.0 与 esbuild 0.25.10，package-lock.json 已锁定。app.js 已打包；页面不取 npm/CDN。

## 真实地点的接入

拍摄重叠、多角度照片 → 摄影测量/扫描 → 用实际长度校准 → 修补、减面、整理材质 → 导出内嵌纹理 GLB → 本页导入核对 → 标记水域/障碍/投喂点 → 应用独立动态水面与鱼群。

单张透视图缺少背面、遮挡和精确深度。水、玻璃、动态植物一般需单独处理。导入器负责显示模型，未自动识别可编辑的池塘、房屋和植物。此版不支持外部文件 glTF、Draco/Meshopt/KTX2 压缩。NeRF / Gaussian Splatting 需另接重建与渲染器。

## 第二轮：补齐水、手与生态（2026-10-02）

[投喂截图](assets/feeding-v2.png) · [抚摸截图](assets/stroking-v2.png) · [青蛙](assets/frog-v2.png) · [乌龟](assets/turtle-v2.png) · [蜻蜓](assets/dragonfly-v2.png) · [移动端](assets/mobile-v2.png)

水体增加双缓冲半浮点模拟、池岸遮罩、独立折射与深度纹理、按水中路径长度计算的吸光；池底深度从0.46m调整为0.78m设计值。硬件不支持浮点渲染目标时仅涟漪回退到解析方式。波形与光斑为实时近似，不是流体工程求解。

该轮骨骼手使用原作的连续 SDF 网格与17骨骼绑定，降低提取密度并采用标准物理材质，旧版保留在 hand-rig-v2.js。第三轮已替换这套手部实现。手先伸出再释放食物；抚摸先引导选中锦鲤靠近，满足接触距离后开始动作。没有鱼时给出提示。拖动、切换视角、自动漫游、导入模型或恢复默认会结束手部动作。

青蛙有静止与伸腿跳跃模型；乌龟有晒台、入水、游泳、返回状态；蜻蜓有飞行、悬停、停栖。行为用模拟时间驱动，暂停后保持状态。动物观察按钮将镜头移动到近景；在画布中可点击动物触发行为。

新增源码 sdf.js、hand-rig.js、animal-anatomy.js 中的改编部分保留原作 MIT 署名；app.js.LEGAL.txt 随打包保留。原作HTML没有变更。

验证：[新增21项记录](notes/v2-validation.json)、[回归24项记录](notes/browser-validation.json)、[界面联动5项记录](notes/ui-v2-validation.json)。动作测试以0.05秒模拟步推进并渲染关键画面；这是行为与画面验证，不是硬件帧率测试。完整季节、潜水镜头、18种锦鲤造型与原作多声源环境仍在原作体验页，尚未全部迁移到独立庭院。

## 第三轮：重做手部与动作（2026-10-02，动作已由第四轮替代）

[同镜头前后对照](assets/hand-before-after-v3.png) · [手背近景](assets/hand-detail-v3.png) · [捏合](assets/hand-pinch-v3.png) · [掌心](assets/hand-palm-v3.png) · [投喂](assets/hand-feeding-v3.png) · [鱼背接触](assets/hand-contact-v3.png)

旧手的形体、关节过硬且肤色均匀。本轮更换为固定版本的通用手网格，修复腕部接缝并延伸前臂，两级细分形成连续曲面；25个手部关节加1个前臂骨骼。五指独立弯曲，捏合时拇指与食指使用逆运动学。指甲共享皮肤骨骼权重，袖口补织纹、褶皱和缝线，避免露出模型内部。

内置 image_gen 新生成 [皮肤颜色贴图](web/assets/hand-skin-albedo-v3.png)，加入细毛孔、浅掌纹、轻微色差和接触后的湿润变化。使用实际三维材质和静止模型坐标投影，纹理随弯指移动。原始生成文件保留；完整提示词、路径、尺寸与SHA-256见 [生成记录](notes/hand-skin-generation.json)。

投喂增加伸手、捏住、分次松指、退场；18粒饲料从实际两指中点按重力落下，落水触发波纹并漂浮，锦鲤靠近后消耗。修复时间边界偶尔漏最后一粒的问题。抚摸增加手掌降落、指尖贴合、掌面间隙检查与抬手退场，避免主干表面穿透。“查看手部细节”提供近景，拖动可旋转到掌心和手背；允许直接进入投喂或抚摸，退出后恢复普通镜头限制。

当前25项手部专项、21项交互/生态回归、24项页面回归、5项界面联动、2项参数测试与研究集10项测试通过。手部与页面脚本/着色器错误0，全部自动资源请求为本地。记录见 [手部检查](notes/hand-validation.json)、[近景捕获](notes/hand-capture.json)、[快照与静态包检查](notes/hand-package-validation.json)。原作9个锁定文件哈希保持一致。

近景形体与动作较旧版改善；仍是通用实时模型配合生成皮肤纹理，未达到真实人体扫描和完整皮下散射的精度。庭院照片级还原的整体验收仍保持 blocked，详见 [视觉验收](design-qa.md)。

## 第八轮：水下清晰度与漂浮细节（2026-10-02，历史实现）

观鱼镜头的折射颜色和深度目标由512px提高到与画布匹配的512–1024px，远景反射仍为512px；近景两者为1024px。目标分别分配，并限制长竖屏高度及显卡纹理上限，避免扩大全部通道。实际1139px宽画布的观鱼镜头采用1024px折射，鱼体边缘、花纹与池底更清楚。

落水时逆解 Gerstner 水面的静止坐标，随后以该坐标采样共享波面：饲料随水平轨道移动，按风强度以小规定速度漂移，并根据风浪与局部波场共同法线倾斜。漂浮后取消空中连续翻滚及额外正弦上下摆动；鱼追逐当前颗粒位置，吞食条件保持实际嘴口判定。岸线与障碍会阻止规定漂流越界。这里是材料坐标运动与规定风流，不是流体速度求解。

七片庭院睡莲采用细分曲面叶片、轻微弯曲与顶点色；中心与倾斜使用同一波面，根部坐标保持固定。叶片作为整体浮动，未计算柔性叶面或茎的动力学。平叶自身阴影和青蛙落脚叶片过亮的叶脉线已弱化，减少三角纹和亮线伪影。

鳞片和鳍条使用屏幕导数估算像素覆盖：近处保留微细节，远处混合平均值并放宽边缘，降低高频纹理混叠。头部粗糙度单独过渡，身体仍按鳞片改变粗糙度。滤波会主动减少远处微细节，不能把它视为更高分辨率的真实扫描纹理。

实现：`water-quality.js`、`floating-motion.js`、`water.js`、`fish.js`、`koi-material.js`、`vegetation.js`与`scene.js`。网页“投喂”和“性能”说明、技术页水面及鱼体对照已同步。
