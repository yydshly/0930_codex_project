# Gaussian Splatting 与毛绒研究理解

更新：2026-10-02。本文记录本轮研究依据、独立高斯分支的范围及可检验的扩展路线。原绒毛实验室、小世界、陪伴工作室和已保存的创作继续保留；文中的“后续”是研发方向。

最新选型见[舒适毛绒效果：方法、工具与制作路线](plush-method-selection.md)。后续外观工作先通过成熟毛发工具和纤维散射建立可验收的原始资产，再比较网页高斯与实时毛发方案。以下历史实现和验证保留，不代表已完成新路线或参考外观。

## 先明确我们在做什么

目标是新增一种表现柔软毛簇的三维外观，并把它的来源、计算和边界写清楚。这个目标同时有两个成果：可以旋转观察与交换资产的独立实验页，以及能够持续维护的研究理解。做出毛绒外观不等于完成毛发物理、照片重建或 AI 陪伴；这些能力需要不同的数据和计算。

现有项目使用 Three.js，但“用了哪个引擎”和“参考了什么方法”是两件事。Three.js 管理相机、场景与 WebGL 资源；本项目在这个底座上选择纤维、层壳或高斯来表示外观，并用独立算法决定运动。新的高斯实验仍可以使用 Three.js，相同底座也不会让不同表示自动兼容。

| 层次 | 回答的问题 | 本项目的对应内容 |
| --- | --- | --- |

## 3DGS 原论文解决的问题

Kerbl、Kopanas、Leimkühler 与 Drettakis 的《3D Gaussian Splatting for Real-Time Radiance Field Rendering》发表于 2023 年。它用带相机标定的静态场景图像和稀疏点云，学习显式三维高斯，组合参数优化、密度控制与快速绘制，实现新视角观察。论文方法不需要在渲染时运行一个大型神经网络；“学习”来自用图像误差优化资产参数。[作者项目页](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/)，[原论文全文](https://arxiv.org/html/2308.04079v1)。

下面保留与本页直接相关的公式，符号改成便于对照代码的形式；这不是完整推导或优化器实现。

### 表示：一个点有形状，而不只是位置

每个高斯包含中心 `μ`、三个正尺度 `s`、单位四元数 `q`、透明度 `o` 与颜色。令 `R(q)` 是旋转矩阵、`S = diag(sx, sy, sz)`：

\[
\Sigma = R S S^T R^T = R\operatorname{diag}(s_x^2,s_y^2,s_z^2)R^T.
\]

`Σ` 是三维协方差，决定椭球在各方向的扩展。对空间位置 `x`，未归一化权重为：

\[
G(x)=\exp\!\left[-\tfrac12(x-\mu)^T\Sigma^{-1}(x-\mu)\right].
\]

中心权重最高，离开中心平滑衰减。狭长高斯能组成方向不同的毛簇；它不保存一根毛的根尖连接、弯曲段或水量。这个差异决定了未来梳理与物理编辑不能直接照搬原表面笔刷。

### 投影：三维椭球变成二维椭圆

取世界到相机变换的线性部分 `W`，在高斯中心计算透视投影的局部 Jacobian `J`：

\[
\Sigma_{2D}=J W\Sigma W^T J^T.
\]

这里 `J` 取屏幕横纵两个输出，因此结果直接是 `2 × 2`；对应原文 Eq. 5 投影后保留横纵子矩阵。屏幕片元与投影中心的距离 `d` 用 `Σ₂D⁻¹` 衡量，形成椭圆高斯权重。旋转角色后椭圆会变化，而非始终面对相机的固定圆点。

这是局部透视近似；高斯太大、靠近相机或跨过近裁剪面时，不能假定近似永远有效。实现应检查有限值、裁剪与最小屏幕足迹，避免放大成覆盖全屏的错误椭圆。

### 合成：顺序影响可见结果

对按由近到远排列、覆盖一个像素的高斯，取该像素的 `αᵢ = oᵢ × G₂D(dᵢ)`：

\[
C=\sum_i c_i\alpha_i\prod_{j<i}(1-\alpha_j).
\]

前面的透明部分才允许后面的颜色透过。浏览器用由远到近的常规 over 混合可得到相应合成。深度只按中心排序仍是近似；大椭圆互相穿过时，所有像素未必共享同一正确顺序。这也是应观察转动跳变、半透明帽缘和轮廓的原因。[原论文 Eq. 3–6](https://arxiv.org/html/2308.04079v1)。

## 本轮实现范围与原论文的距离

独立 `splat.html` 分支按种子生成软星等程序角色，资产字段是真实三维均值、尺度、旋转、透明度和常数颜色；绘制采用上述协方差投影、椭圆权重与深度排序透明混合。毛色、毛簇蓬松度与点数等控件调整程序资产，旋转用于观察表示，PLY 导入导出用于交换资产。具体控制项和通过的检查应以最终代码与验收记录为准。

| 项目 | 本轮范围 | 尚未实现或不能据此推断 |
| --- | --- | --- |
| 高斯数据 | 程序生成均值、尺度、旋转与透明度 | 由照片恢复真实毛绒物体 |
| 椭圆绘制 | 三维协方差投影，深度排序与 alpha 混合 | 原论文 CUDA tile 栅格器与性能结果 |
| 外观颜色 | 常数颜色，可用程序计算外观色 | 高阶球谐方向颜色、物理重照明 |
| 参数调整 | 从种子与控件重新构造外观 | 反向传播、图像损失、增密、拆分、剪枝训练 |
| 资产交换 | 受支持的 PLY 高斯字段 | 任意 PLY 都是高斯，或所有导出工具都兼容 |
| 旋转观察 | 改变相机或整体模型角度 | 骨骼变形、逐根梳理、柔软按压和毛发受力 |
| 参考外观 | 探索截图中的毛簇与软轮廓方向 | 复现参考视频的完整管线或同等画质 |

原论文的训练需要渲染后与训练图像比较，优化参数，并按需要调整高斯数量；本轮没有这部分输入与计算。[作者训练代码和数据说明](https://github.com/graphdeco-inria/gaussian-splatting)。因此准确称呼是“程序化 3D 高斯毛绒表示与绘制实验”。

PLY 是承载字段的格式，普通位置/颜色点云和含高斯尺度、旋转、透明度的资产应分开识别。不同工具还可能用对数尺度、透明度 logit 或球谐系数编码。导入时必须按支持的字段转换并验证，不能把名字相似的属性直接当成物理尺度。导入成功只证明解析和绘制兼容，不证明资产来源或训练质量。

## 与既有三篇毛绒研究如何连接

这四个研究方向回答不同问题，可以互补。以下保留现有实现范围，不把新理解改写成旧页面已经拥有的能力。

| 研究 | 主要问题 | 核心思路 | 项目当前理解层次 |
| --- | --- | --- | --- |
| Lengyel 等，2001 | 如何实时表现绒毛厚度与侧面轮廓？ | Shell 体积切片、轮廓 fins 与 lapped textures | 采用层壳部分，尚无 fins 和 lapped 映射 |
| Müller 等，2012 | 如何让细长毛发运动而保持段长？ | 从固定根顺序保长投影，并修正动态速度 | 32 根六段导向链的核心算法近似 |
| Fei 等，2017 | 水如何流动、聚束并反过来影响毛发？ | 杆模型、薄液层、液桥与流体交换 | 当前仅聚集外观启发 |
| Kerbl 等，2023 | 如何学习场景外观并快速画出新视角？ | 可优化的各向异性高斯与有序透明绘制 | 本轮程序资产与前向绘制，未接训练 |

### Shell：便宜的绒毛体积近似

Lengyel 等将毛发体积采样为多层透明纹理，再在身体外画 Shell；fins 改善掠射角的轮廓，lapped textures 用局部贴片映射复杂曲面。它主要解决绘制与映射，不是完整毛发动力学。[作者资料](https://www.hhoppe.com/proj/fur/)，[原论文](https://www.hhoppe.com/fur.pdf)。

本项目使用 32 层 Shell 与程序截面纹理，提供剪切式风吹和共享按压；没有 fins、lapped 映射或完整论文光照。选择它的价值是以较少几何表现短绒厚度，代价是侧视、星角和透明叠层仍可能露出限制。验收应比较正面与侧面、远近缩放、暂停后稳定性，以及切回原纤维时记录是否保留。本轮不改变 Shell 暂不支持局部创作与简化接触的边界。

### 动态 FTL：顺序保长，加上速度修正

Müller 等把一根毛作为粒子链，从固定根部逐段将预测位置投到距已修正前一粒子为静止段长的球面；动态 FTL 再把下一粒子的投影修正量加入当前速度更新，缓解直接 FTL 的异常质量分布。其 Eq. 9 可写为 `vᵢ = (pᵢ − xᵢ)/Δt − s_damping·dᵢ₊₁/Δt`；`d` 是投影造成的位移。[原论文](https://matthias-research.github.io/pages/publications/FTLHairFur.pdf)。

本项目求解少量导向链，渲染毛束插值跟随，并额外引入自己的静止形态目标、回弹和阻尼。它的价值是让梳理后毛流与运动连接，控制成本；它不保证每根渲染毛都拥有独立物理约束。应检查固定根、每段长度误差、大时间步与强风稳定，以及梳理目标恢复。原论文还讨论毛发之间的密度网格作用，本项目没有把这部分当作已完成能力。

### 湿毛：外观聚束与液体求解之间的距离

Fei 等的多尺度模型连接毛发离散杆、沿毛的薄液层流动、液桥表面张力以及周围液体交换，从而处理润湿、聚束与滴落。核心是液体输运和毛发受力共同演化。[作者资料](https://www.cs.columbia.edu/cg/liquidhair/)，[原论文](https://www.cs.columbia.edu/cg/liquidhair/figs/wethair_reduced.pdf)。

目前本项目只有毛尖向固定毛束中心聚集、湿润配色和根部遮蔽。它能提供“看起来较湿、毛发聚成束”的创作参数，不能用来预测水量、滴落或干燥时间。根部变暗不等于真实毛发自阴影。下一步适合先做可观察的两束液桥小实验：记录含水量、间距、聚合与分开，检查水量守恒和力随距离的变化，再讨论完整流体耦合。

### 页面范围要保持明确

原实验室 `index.html` 可以选择三项论文实验。小世界 `world.html` 使用默认 `FurCoat`，没有自动开启它们；陪伴工作室 `studio.html` 嵌入小世界，增加生活记录和任务展示。新增 `splat.html` 是第四种独立研究入口。本轮不会因为文档汇总四篇论文，就把各页面都描述成已经集成四种完整算法。

## 对毛绒工作室真正有价值的地方

这是针对我们产品方向的判断，而非论文已经验证的产品结论。

高斯可以提供复杂静态外观与软轮廓的资产路线：用户观察、搭配或展示角色时，不必把每处外观都表示为可单独编辑的纤维。程序生成先让表示和参数可见；如果后续导入用自有多视角素材训练的资产，再验证它能否保留我们喜欢的密实短绒与细节。

原纤维仍适合明确的创作语义：毛根在哪里、哪里剪短、朝哪个方向梳。高斯只是重叠体积贡献，删除几个高斯不必然等于剪掉一撮毛，旋转一批高斯也不必然等于真实梳理。若要互通，需要建立高斯到角色表面、毛簇或骨骼的绑定，并定义编辑前后的可预期结果。

混合方向可以让高斯承担复杂外观、原几何承担眼睛和配饰、导向链承担可控运动，但透明排序、遮挡和变形都要重新验证。陪伴笔记、提醒、故事与 Agent 执行则继续由工作室状态管理，再驱动角色动作。好看的三维表示是展示层价值，长期陪伴价值仍来自可靠的记忆、任务和用户控制。

## 怎样检验，不把数值测试当画质结论

| 检验层次 | 具体办法 | 能支持的结论 |
| --- | --- | --- |
| 数值与资产 | 检查均值有限、尺度正值、单位四元数、透明度范围；同种子重建；PLY 往返 | 数据有效、可重现与格式受支持 |
| 协方差投影 | 使用轴对齐与旋转的已知椭球；比较投影主轴，检查近裁剪与缩放 | 三维方向进入了屏幕椭圆 |
| 遮挡与合成 | 两个不同色半透明高斯交叠，交换深度；对照 CPU alpha 计算 | 排序与透明混合符合约定 |
| 浏览器画面 | 实际旋转整圈，缩放与调整毛簇；观察眼睛、帽缘、轮廓和排序跳变 | 在该浏览器和视角下显示与交互正确 |
| 与旧纤维比较 | 固定相机、背景、输出尺寸和颜色，记录两种表示的截图与参数 | 这个条件下的外观差异，不能推及所有素材 |
| 性能 | 记录设备、浏览器、点数、分辨率、帧耗时与内存；真实手机持续运行 | 指定环境的成本与稳定性 |
| 未来训练 | 自有多视角素材，明确训练/保留视角，记录重建误差与异常区域 | 训练资产的新视角质量 |

当前程序资产没有真实参考照片，不能给它填写虚构 PSNR、SSIM、LPIPS 或训练时间；画面漂亮也不能代替段长、液桥或碰撞检查。测试和实机检查的具体结果应追加进项目记录，标明时间、环境与仍未覆盖的边界。

## 可扩展路线

## 外观细化与像素过滤理解 · 2026-10-02

### 为什么采用高斯之后，画面仍不自动逼真

3DGS 规定了怎样表示和绘制外观，真实感还取决于资产内容。原论文从多视角图像及相机信息优化高斯参数，外观细节来自观测与拟合；本页由规则生成毛根、曲线、尺度和颜色，没有照片监督。增加点数能增加可表达的细节，不能自动获得照片中的材质、遮蔽或反光；还要让毛簇密度、尺度、体积明暗与整体毛流一致。用户截图可以作为造型与外观目标，但截图本身没有证实对方用了哪种训练素材或完整生成流程。[Kerbl 等原论文与作者项目](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/)。

本次程序资产采用泰迪短卷毛簇。以表面切向的下垂方向建立局部坐标，再用固定种子打散卷面方向、相位、左右旋、半径、高度和椭圆率；毛根沿两个切向轴抖动，弧段的采样位置也有小幅变化，目的是减少重复孔纹与钩针感。主体毛簇预算为一个暗根高斯与六段有起伏的环弧高斯，多数协方差长轴沿该段曲线方向排列，约 19% 弧段替换为更短、更薄的随机碎毛。底壳较暗，环弧按局部法线与根部遮蔽计算明暗；帽缘与眼窝另加局部遮蔽，帽子增加褶皱及方向、相位与根点均打散的短卷织纹。眼睛用椭球法线计算解析的窗灯、地平线和边缘反光图案，再将结果写入每个高斯的线性 RGB。

这些是**生成时烘焙的常数色外观**：根部 AO 是遮蔽近似，不是实时自阴影；毛流是几何构造，不是毛发受力求解；眼睛反光随资产一起转动，不会根据新视角重算。切换展台背景没有重新照亮角色。导出 PLY 也只带这些颜色，目前没有可重光照材质、真实阴影图或方向相关高光。

### Mip-Splatting：防止小高斯在屏幕上被无偿放大

Yu 等的 **Mip-Splatting（CVPR 2024）** 将三维平滑与二维像素过滤结合起来处理不同采样尺度。§5.2 的式（10）用二维高斯近似像素面积积分；§6.1 给出二维过滤方差 `0.1`。本项目只采用这一二维部分：投影协方差 `C` 以绘制缓冲区像素平方为单位，加上 `sI` 扩展足迹，同时降低峰值透明度。[原论文 §5.1、§5.2、§6.1](https://www.cvlibs.net/publications/Yu2024CVPR.pdf)。

```text
C_filtered = C + sI,                         s = 0.1 px²
opacity_scale = sqrt(det(C) / det(C_filtered))
alpha(x) = opacity × opacity_scale
           × exp(-½ (x - center)ᵀ C_filtered⁻¹ (x - center))
```

只扩大椭圆、保持峰值不变，会增加小高斯的覆盖贡献；细毛缩到一个像素以下时容易变厚、变亮。行列式比补偿的是单个未截断高斯的积分。实际绘制还有三倍标准差截断、低透明度丢弃、裁剪及多层 alpha 混合，因此不能据此声称整幅图亮度严格守恒。

这里没有论文 §5.1 根据训练相机采样频率约束三维高斯的过滤，也没有多视角优化。文档应称为“借鉴 Mip-Splatting 的二维像素过滤”，不能称为完整复现或保证所有缩放比例无混叠。该过滤解决采样问题，也不会替资产补出毛发细节或正确光照。

### 线性合成与显示颜色为什么要分开

透明层需要先在线性颜色中合成，再把最终画面转换到显示用 sRGB。Three.js 官方文档将 Linear-sRGB 作为工作空间，后处理输出使用 `OutputPass`；它也说明线性渲染目标可能需要半浮点精度，避免把线性计算与显示编码混为一谈。[Three.js 色彩管理](https://threejs.org/manual/pages/color-management.html)。

本页将角色和实际展台背景放入同一个线性离屏目标中，最后统一输出；支持浮点颜色缓冲时使用半浮点，缺少支持则回退到 8 位线性目标。回退能继续显示，但量化精度不同，仍需实机检查暗部渐变。外观颜色的计算与最终显示转换是两件事；修正色彩流程不等于新增物理光照。

### 精细度、检查方式与后续方向

页面新增 80,000 档和毛绒特写，原 18,000 / 32,000 / 50,000 档继续可用。首次在 700px 及以下窄屏打开、没有本机搭配时使用 32,000 档，已有保存与分享参数优先。新版增加点数时主要增加卷簇数量，保持卷簇高度参数，缓慢缩小环弧半径与截面；同种子仍可重建当前算法的同一资产，但外观算法升级会改变旧参数重新生成的结果。

检查时固定种子、相机、画幅和背景，对照卷簇边缘、帽缘和眼睛；再逐步缩远与靠近，观察足迹变化、亮度膨胀及排序跳变。数值检查可用 `C = diag(0.01, 0.01)`：加 `0.1I` 后，峰值补偿为 `0.01 / 0.11`，与扩大后的足迹一起对照。将过滤开关或点数变化造成的效果，与烘焙外观变化分别比较；这些办法不是已经完成的新画质或性能验收。

下一条可检验的路线是建立自有 Blender 毛绒场景与多视角图像，保留未参与训练的视角，对照程序资产与训练资产。若要随灯光和观察方向出现新反光，还需要方向颜色或明确的可重光照表示；若要剪修与梳理，仍需给高斯绑定毛根和可编辑曲线。以上每步都应保留原页面与创作数据，并单独追加测试环境和证据，不能沿用上一轮验收数量来证明本次修改。
