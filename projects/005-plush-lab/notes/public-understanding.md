## 我们在做什么

毛绒实验室是一组把角色创作、世界互动、个人生活记录和方法研究连接起来的网页工作台。它的起点是用户想要的舒适、细密、自然卷绒质感；后来加入自由搭配、随机创意、着装、可布置的场景、故事成长的基础、陪伴笔记与提醒，以及 Agent 执行过程的可视化。

最终目标不是不断增加演示参数，而是让一个喜欢的角色能进入日常创作与记录：形象可以控制，结果可以保存，互动有真实反馈，方法和修改有来龙去脉。真实 AI 将来可以连接笔记、提醒草稿、记忆和行动，但它当前还没有启用。

此前页面、作品、配方、全部历史条目和本机研究工程都继续保留。项目全景按 10 个阶段组织 124 条内置记录与同来源下的个人补充，另列 9 组方法、当前能力、已发现问题与 6 个扩展方向。

## 两条毛绒路线为什么同时存在

| 路线 | 当前价值 | 当前能力 | 不能由此推导的能力 |
| --- | --- | --- | --- |
| 程序纤维 | 毛根、长度、卷曲和笔刷语义明确，适合自由创作 | 八种形状与材质、配饰、风触碰、局部剪染卷梳恢复、组合步骤、检查点与保存 | 完整纤维物理散射、逐根接触、柔软填充物、参考质感已达标 |
| 原作 3DGS / Spark | 保留目标角色复杂静态外观，能够直接观察并进入场景 | 完整本地高斯、SH3、整体动作、色调尺度、相对毛长、附加卷曲、连续梳理 | 我们自行生成或训练了原作、真实毛根、局部剪染换装、动态重光照或逐根动力学 |

程序毛丝是带形体与毛根的几何表示；高斯是带位置、尺度、朝向、透明度和颜色信息的空间椭球。它们共享 Three.js / WebGL 的场景、相机和输入基础，但编辑和模拟语义不同。只有先确定所需能力，再选择表示、算法、工具与资产，才能兼顾舒适质感和可控创作。

参考角色 **ChatGPT dots - Felipe** 由 **abstrakt** 制作，[公开场景](https://superspl.at/scene/ca6a4c9b)使用 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。本项目将六个 SOG 分块保存为许可资产，保留 **3,493,379 个高斯与 SH3**，共 66,929,437 字节，约 66.9 MB；具体来源、文件与校验见[资产清单](../web/assets/reference-plush/manifest.json)。本项目贡献是加载、坐标转换、归一尺度、场景合成、交互与近似编辑，制作署名与项目适配职责分别保留。

## 底层实现怎样连接

**程序创作：**在形体上采样毛根，用线段与渐细 ribbon 表达毛丝，插值稀疏导向来实现弯曲和随动。局部长度、卷曲、覆盖及颜色写入 128×64 表面场；近期笔触达到 512 个时合并到无损 Float32 检查点，保留已有效果，再继续记录新操作。共享历史记录最近 24 步，组合步骤能把多个工具操作共同记为一步。风、按压、身体及配饰接触都是当前网页范围内的近似。

**原作显示：**Spark 2.3.1 逐块解码 SOG，GPU 计算球谐颜色，worker 排序高斯；固定 X 轴 π 旋转后居中并归一到 2.2 场景单位高度，再接入三个现有画布。整体变换负责行走、坐下和弹跳；毛长 0.65–1.65 倍、附加卷曲 0–100% 与 12×14×8 梳理场改变显示时的位置、方向和尺度。0% 附加卷曲保留原卷度。选择绒毛依赖原始颜色与空间范围，尚无完整语义分区。原作烘焙外观和视角相关颜色仍保留，场景灯光不重新计算纤维散射。

**小世界：**种子和配置生成造型、材质、配色、着装与场景；用户可以锁定搭配组、摆放家具、保存草稿和收藏。状态机、路径、代理几何与运动学协调角色行动。球在地面完成三次逐步变小的抛物线弹跳，再滚到目标；角色开始追逐，等球落稳且自己到达后才拾取。暂停会冻结双方，游戏临时状态不写入长期作品配方。这个流程有确定反馈，但不是完整刚体或骨骼求解器。

**记录与任务：**作品、项目记录、陪伴笔记和提醒各自保存，读取时校验结构，不互相覆盖。固定任务读取数据快照，按规则组织工具结果并生成可编辑草稿，步骤开始、完成、失败、取消等事件驱动可视化。任务结果不会自行写成笔记或修改提醒；实际用户操作和角色互动事件才形成共同回忆和成长里程碑。

## 陪伴价值现在在哪里，AI 将来接在哪里

当前陪伴工作室能写、编辑、搜索和导出笔记，安排页面内提醒，查看共同回忆与成长。提醒在页面运行期间定期检查，回到前台补查；关页后没有推送。成长依据打招呼、完成捡球、保存笔记和完成提醒等真实事件，不靠离线扣减数值制造负担。

Agent 面板有三个固定本地任务：**整理我的笔记、检查提醒安排、生成工作室概览**。可以逐步继续、自动推进、暂停、停止，查看实际工具结果并编辑草稿。它表达真实执行流程，尚无模型自主规划、多个 Agent 协作或后台调度。

[当前接口](../server/README.md)明确标记外部 AI 未启用，`/api/status` 返回未接入，`/api/chat` 返回 `ai_not_enabled`，没有用本地规则冒充模型回复。笔记的未来分享选项默认关闭，也不会把全部旧创作自动变成 AI 上下文。

后续 AI 的价值可以围绕真实用途形成：用户选择想分享的笔记与记忆，模型帮助整理和理解，再提出笔记、提醒或行动草稿；用户检查之后才保存或执行。行动结果经工具核验，再映射到毛绒角色状态。长期故事、养成和提醒能力需要分别设计记忆保存、纠错、跨设备和后台执行机制。

## 论文与成熟工具分别解决什么

| 论文 / 工具 | 它解决的问题 | 本项目采用范围 |
| --- | --- | --- |
| [Lengyel · Shells / Fins，2001](https://www.hhoppe.com/proj/fur/) | 以分层曲面近似毛层体积，轮廓 fins 补边缘 | 已运行 32 层短绒；没有完整 fins 或 lapped textures |
| [Müller · 动态 FTL，2012](https://matthias-research.github.io/pages/publications/FTLHairFur.pdf) | 固定毛根、逐段保长投影与速度修正 | 已运行 32 根六段稀疏导向；没有逐根 CUDA、密度网格与毛发互斥 |
| [Fei · 液体与毛发，2017](https://www.cs.columbia.edu/cg/liquidhair/) | 毛发受力、液膜流动及液桥表面张力耦合 | 采用湿润颜色、毛尖聚束和根部遮蔽外观；没有液体输运、守恒、滴落或干燥求解 |
| [Chiang · 纤维散射，2016](https://www.disneyanimation.com/publications/a-practical-and-controllable-hair-and-fur-model-for-production-path-tracing/) | 光在纤维中的反射、透射及内部传播 | 在 Blender / Cycles 中实际运行；仍需合适的毛束几何、灯光和视觉验收 |
| [Kerbl · 3DGS，2023](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/) | 从标定多视图优化高斯并合成新视角 | 程序前向绘制及既有训练资产显示；没有本项目多视图训练或照片重建 |
| [Yu · Mip-Splatting，2024](https://www.cvlibs.net/publications/Yu2024CVPR.pdf) | 抗缩放混叠与更稳定的高斯过滤 | 程序展台采用二维像素过滤、透明度补偿；未实现训练时三维平滑，原作分支由 Spark 单独显示 |
| [Blender Hair Nodes](https://docs.blender.org/manual/en/latest/modeling/geometry_nodes/hair/index.html) / [Houdini Groom](https://www.sidefx.com/docs/houdini/fur/teddybear.html) | 导向、插值、卷曲、结簇、毛束层级与 groom 制作 | Blender 官方节点已实际运行；Houdini 是方法参考，未运行其分束与接触求解器 |
| [LichtFeld](https://github.com/MrNeRF/LichtFeld-Studio) / [SuperSplat](https://github.com/playcanvas/supersplat) / Spark | 高斯训练、编辑发布、解码显示的不同环节 | 未运行 LichtFeld 训练；历史官方查看器和当前 Spark 本地显示都保留 |
| [GaussianHair](https://arxiv.org/html/2402.10483v1) / [Volumetric Sheen](https://www.disneyanimation.com/publications/practical-volumetric-sheen/) | 发丝连接、重建与编辑，短纤维表面光泽 | 已整理输入与适用条件，尚未集成；不能直接当作单图毛绒生成能力 |

详细公式与实现差异见[高斯与毛发理解](gaussian-splatting.md)、[方法选型](plush-method-selection.md)、[初期研究](research.md)和[Cycles 全部制作记录](cycles-material-study.md)。代码负责把选择落地，研究帮助选择正确的表示与约束，产品和工具提供可用管线；三者共同服务具体视觉与交互目标。

## 我们已经积累了什么

发展过程完整保留：舒适短绒与自由搭配 → 持续局部创作 → 项目记录 → 随机搭配和小世界 → 陪伴与固定任务 → 论文与程序高斯实验 → Blender / Cycles 真实样片 → 在线原作基准 → 原作本地同画布接入与控制 → 页面体验审查。

GN1–GN14、V15 完整成片与 V16 预览证明相关制作与渲染实际运行过，但用户仍认为自制质感没有达到参考，因此它们是保留研究候选。历史单轮测试数量、桌面帧率和截图不能作为全部功能、全部 GPU 或真实手机的统一结论，也不能替代视觉认可。

本机保留 54 个大型 `.blend` 工程，约 3.6 GB。公网提供脚本、参数、样片与日志，不发布真实工程文件；[工程材料说明](../web/engineering.html)解释保留范围。公开说明页不能冒充工程下载，本地工程也没有因为网页发布而被删除。

## 适用场景和对我的意义

创作时，它让形象、配色、材质与局部手工修改有可保存的过程；学习时，它让论文、工具、参数和结果相互对应；复盘时，它保留成功与失败，下一轮不用从头猜方法；生活中，它把笔记、提醒与真实互动放进同一个柔和的入口；展示 Agent 时，它提供可观察、可停止的执行事件与结果。

对我们而言，价值在于形成一个可以长期维护的个人空间：喜欢的形象、自己的想法和实际做过的事都有记录，创作与理解能够继续增长。现有毛绒表现提供入口，未来 AI 与可靠执行能力才可能带来更完整的陪伴、故事和行动价值。

## 使用与数据保存

先看[项目全景](../web/project.html)与引导图，再到[绒毛创作](../web/index.html)试程序角色或[原作模式](../web/index.html?plushView=reference)的相对毛长和附加卷曲；去[小世界](../web/world.html)搭配、布置与互动，或到[陪伴工作室](../web/studio.html)记录和运行固定任务；保存作品，再用项目记录补充理由与下一步。全部 6 个原有 web 页面、4 个资料页面及新增工程说明可从[网页入口表](../web/README.md)找到。

公网地址、localhost 和 127.0.0.1 是不同来源，浏览器数据不会自动迁移。旧作品仍在原来源，可继续打开；按模块现有的配方、作品分享或导入能力迁移支持的格式。项目个人记录有 JSON 备份与合并导入，陪伴记录有 JSON / Markdown 导出但尚无恢复导入。当前没有账号、云同步或跨设备长期记忆。

## 下一步如何推进

1. 修复已确认的页面问题：面板与角色状态、梳理和布置互斥、导入容量、笔刷范围命中与近景反馈、窄屏预览、键盘与可读性。
2. 给目标资产建立身体、帽子、眼睛和衣物的语义区域，再选择局部剪染、换装和柔软形变路线；真实逐根控制需有对应毛根、绑定或毛丝资产。
3. 接入真实 AI，先完成用户选择记忆、可编辑草稿、结果核验与实际保存，再扩展长期陪伴、提醒和故事。
4. 在真实任务事件流上扩展受限规划与执行，角色只表达已验证的工具状态与结果。
5. 扩展主题搭配、场景物件、多角色和共同故事，让养成依据实际活动与记录。
6. 测首次加载、显存、不同 GPU 和真实手机，再做按需加载、分级质量、作品版本与跨设备方案，保留母版和旧作品。

这些方向均待完成；当前可以直接使用的能力和研究候选应分别验收。完整资料汇总为后续选择提供基础，不用承诺所有扩展已经实现。
