# 当前版本：物理成因演示

用户要求理解黑洞是什么、如何形成，以及原图现象如何产生。当前默认是恒星平衡到成洞、气体与能量、光路到成像的科学流程，见 [SCIENCE.md](SCIENCE.md)。当前验收在 validation.json；下面为之前版本的研究记录，包含已被替换的着色器构造流程。

# 本轮研究记录

- 日期：2026-10-02（Asia/Shanghai）。
- 来源：VOLDR_dev 的 Reddit 黑洞展示；原作公开仓库与 commit 尚未确认。
- 环境：Windows、Python 3、Node.js、Chromium / SwiftShader、WebGL 2。
- 目标：先做可交互效果，再用对照实验说明原理、适用场景与扩展方向。

## 设计与实现

采用无运行依赖的静态网页。片元着色器在三维空间积分近似弯曲光路，逐步采样吸积盘发光和远方星空；JavaScript 管理相机、参数、质量、调度与 PNG 输出。

首次纯体积盘面采样在侧视时过度平滑，改为弱体积层加薄盘中平面交点采样，保留径向条带。当前公式与模型限制见 [PRINCIPLES.md](PRINCIPLES.md)。

连续软件渲染验收发现 GPU 队列积压，加入 WebGL 2 fence，上一帧完成后再提交下一帧，避免交互与导出被大量待执行帧阻塞。单独导出检查确认有效 PNG。

预览时发现常用端口已经被其他项目占用，改用系统分配的空闲端口，未终止其他项目的服务器。终端沙箱启动异常，通过工作区范围内的替代执行完成本次文件和验收操作。

## 验证证据

真实浏览器验收检查 Shader 编译、图像黑区与发光区域、透镜开关的像素差、盘面开关、亮度变化、暂停与恢复、相机操作、质量档位、PNG 导出、教学按钮、窄屏布局和无 WebGL 时的说明。

详细结果见 [validation.json](validation.json)，截图位于 [assets](../assets/)。自动测试使用软件渲染和移动视口模拟；硬件帧率、手机 GPU 表现与完整 GR 精度没有在本轮验证。

## 后续优先项

1. 为教学显示单条光路与真实盘面位置。
2. 增加细环与星点过滤，进行目标 GPU 帧时测量。
3. 按玩法需要接入局部物体透镜与引力逻辑。
4. 再考虑严格的测地线初值、频移和引擎移植。


## 从零到有的体验修正

用户指出页面应呈现从零到有的过程。默认入口已改为空白，按 00–07 阶段依次加入星空、捕获区域、平面盘、流动纹理、弯曲光路和运动增亮，完成后才开放自由实验。新增阶段任务、连续权重调整、按住前后对比、自动推进和重新开始；底部完整效果实验也在完成前保持禁用。

主流程与原有功能通过 54 项真实浏览器检查，自动推进、复位和构造入口的专项记录见 [construction-validation.json](construction-validation.json)。这次默认入口与上次直接展示完整效果的入口不同，详见 [构造说明](CONSTRUCTION.md)。
