## 图中的 Agent 应当怎样理解？

Agent 的模型负责理解、判断和生成，工具负责读写文件、运行命令等动作。你提供目标和验收条件；项目提供可读取的规则、状态和资料；运行检查提供结果反馈。

工作闭环是：读目标/规则/状态 → 选择一个任务 → 使用工具执行 → 运行验证 → 失败后修正或停止 → 保存进度和证据。这个库提供的是帮助建立该闭环的方法、模板和局部工具。

## 四个逐步构建的目标

1. **Agent 可读的项目**：启动方法、需求、架构与约束可发现。
2. **有证据的单任务执行**：明确完成标准，依据实际结果验收。
3. **可跨会话接续的长任务**：状态、阻塞、下一步留在项目中。
4. **有边界的自动循环与多 Agent**：增加执行器、重试、预算、持久化与任务归属后，才能可靠地自动推进和分工。

第四级是需要外部接入与二次实现的目标，不能由安装这个 Skill 自动获得。图中强调先做验收和状态，是本研究的采用建议。

## 对当前研究集的意义

把每次研究的版本、能力、证据、边界、使用方法和交付检查标准化，减少换会话后的重复解释和重复调查。已有的编号清单与检查脚本可以继续复用，不需要为了结构分数再复制一套重复规则。

适合持续开发、修复重构、批量迁移、补测试、多角色评审和项目研究；简单问答或一次性小任务只选必要的轻量模板。
