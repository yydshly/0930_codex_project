# 扩展方向与落地建议

以下为本研究提出的建议，不是上游已经实现的能力。

## 先按问题补能力

| 优先级 | 扩展项 | 为什么做 | 最小验收 |
| --- | --- | --- | --- |
| P0 | 真实验收入口 | 结构满分不能判断任务完成 | 一个故意破坏的功能能被检查阻断 |
| P0 | 状态 Schema 与完成证据 | 任意状态字符串目前也可通过 | 非法状态、缺依赖、无证据完成均被拒绝 |
| P0 | 统一模板和文档路径 | 多种文件名/协议容易混用 | 所有入口指向实际存在文件，P07/P08 描述准确 |
| P0 | 修正检查器退出行为 | 扫描问题后仍退出 0 会误放行 | 已知坏样例返回失败，缺目录明确失败 |
| P1 | Windows/跨平台入口 | 当前生成 Bash 与本地 PowerShell 不同 | 同一项目在目标平台执行相同验收 |
| P1 | 真实 Agent 评估器 | 现有 eval 是结构覆盖 | 固定任务逐条执行，保留输出与独立判定 |
| P1 | 可恢复状态与重试预算 | 长任务中断或空转 | 重启可接续；达到预算/重复失败后停止 |
| P2 | 多 Agent 协调 | 并行提高吞吐但增加冲突 | 文件归属清晰、集成检查可阻断冲突 |
| P2 | 领域专用模板 | 通用字段不能表达所有业务验收 | 每个领域有代表性成功和失败案例 |
| P2 | 监控与外部系统接入 | 工具现无生产运行面板 | 可追踪任务、成本、证据和需要人工处理的原因 |

## 方向一：从“检查文件”到“检查行为”

保留当前结构检查作为入门诊断，增加可执行的业务验证契约：

- 每项功能有用户行为、输入、预期结果、验证命令。
- 证据至少记录任务 ID、代码版本、执行时间、命令、退出码和必要产物。
- 完成状态与本次代码版本绑定，修改后使旧证据失效。
- 检查器不可只信任 Agent 自己填写的“通过”。

先做一个能捕获真实回归的检查，比增加十条泛化规则更有价值。

## 方向二：统一状态管理

最小版本仍可用 JSON，但应校验任务 ID 唯一、依赖存在、无依赖环、状态迁移合法。多个工作者参与后，建议增加任务归属、乐观锁/版本号或数据库事务。

持久化应区分三种数据：当前可恢复状态、追加的事件日志、体积较大的验证产物。进度说明给人阅读，结构化状态给程序路由，不要让自由文本同时承担所有角色。

## 方向三：把循环接成真实系统

建议按以下顺序实现：

1. 接入一次真实模型/Agent 调用，明确输入输出。
2. 接入受控项目工具与实际验证。
3. 给 Checker 独立验收标准，优先使用确定性检查。
4. 分类失败：代码问题、环境问题、需求不清、权限问题。
5. 失败回传完整证据；限定轮数、时间和总费用。
6. 把检查点写到持久存储；重启不能重复做不可逆动作。
7. 只有确实需要时再增加并行节点和人工审批节点。

这些需要外部执行环境。改写提示模板不会自动获得调度、进程恢复或事务能力。

## 方向四：将示例知识库产品化

要得到真实知识库，应另行增加：

- 文档解析：PDF、Office、编码识别以及需要时的 OCR。
- 检索：分词、embedding、混合检索、重排和权限过滤。
- 生成：模型适配、引用约束、无证据回答策略。
- 数据：增量失效、删除传播、事务、备份与恢复。
- 验收：固定问答集、引用正确性、无答案案例、延迟与费用。

不要把“多接一个模型 API”当成产品化完成；当前检索、索引和数据一致性也需要补齐。

## 方向五：用于你的项目研究流程

可从现有研究集上做一个轻量模板，不新增复杂平台：

| 阶段 | 输入 | 产物 | 验收 |
| --- | --- | --- | --- |
| 固定版本 | 仓库 URL | commit、许可、文件索引 | 来源明确、哈希匹配 |
| 能力盘点 | 源码和说明 | 输入/产物/机制/边界矩阵 | 宣称与实现分开 |
| 复现 | 明确的功能路径 | 环境、步骤、日志 | 实测和未测分开 |
| 结论 | 所有证据 | 场景、价值、缺口和扩展 | 不把模拟当真实效果 |
| 交付 | 文档与资料 | 清单、阅读入口、图片 | 本地链接、显示与目录检查 |

本轮新建的子项目已按这个思路组织研究产物；它不是在工作区安装了一套通用 Agent 系统。

## 如何做真实收益对照？

从同一代码起点选 3–5 个有明确验收的小任务，尽量保持模型、工具、时间预算和任务难度一致。比较采用前后：

- 任务成功率：按独立验收计算，不按 Agent 自述。
- 人工介入次数和总时间。
- 返工、回归和错误完成次数。
- 端到端耗时与模型/运行费用。
- 换会话后的恢复时间。
- 规则和状态维护成本。

样本小的时候只作为试点观察；不要从一两个成功案例宣称稳定提升百分比。扩展顺序建议为：**真实验收 → 准确状态 → 可靠恢复 → 自动循环 → 按需并行**。
