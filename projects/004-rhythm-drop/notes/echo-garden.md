### 新体验

- 首屏是月夜湖岸与可生长的声音植物。录音和身份设置只在需要时打开；补充背景、表达意图和主动心情折叠为选填。
- “听一段相遇”是 42 秒原创音乐与文字故事：新城市的第一晚 → 一段回应抵达 → 两种声音共生。钢琴动机、立体声回应、低音与和声扩展共同推动三幕；末尾四秒淡出。演示没有真人或合成人声，也不作为社区留言入库。
- 植物从小株到双枝，随着听完与回应变化。实时 FFT 的低频驱动涟漪，中高频带动叶片和光点；声音草稿的分段能量生成稳定的枝长特征，不推断人的性格或情绪。
- 真人漂流继续使用实际投放、倾听、回应与双方交流意愿。重听共同植物时回到湖岸，顺序播放原音频，保留原声来源与声景设置。
- 草稿可收起后继续；收起录音或离开页面会停止录音。声音故事与录音、草稿试听、真实声音播放互斥；页面隐藏时停止故事。提供静音、夜雨、微风、留白与减少动态适配。
- 没有参与者时直接显示安静的湖面；场景故事和真实漂流分别标注，不伪造社区活跃度。

背景使用内置 Image Gen 生成，保存在 `web/garden/drift/lake-night.png`。完整生成提示、来源和用途见 `notes/drift-assets.json`。植物是实时声音可视化，并非静态插画。新的首屏、故事转折、结尾与手机截图保存在 `assets/drift-v11-*.jpg`。

价值假设仍需要真人体验验证：一个人是否更愿意表达，另一个人是否愿意认真听完并回应。视觉改善和流程测试通过，并不能证明这一假设已经成立。

## v0.10 · 保留的产品闭环

## 产品定义

用户提出，让声音关联真实人物，形成类似漂流瓶的表达与社区能力。产品围绕一个具体闭环：**留下声音 → 一位体验者接住并听完 → 用声音回应 → 长出共同植物 → 双方愿意时继续交流**。

希望验证的价值是“表达被认真听见，并得到有意义的声音回应”。植物保存表达、来源与关系；背景声音为人声提供场景。社区版使用共生与回应，个人生态实验中的吞噬仍保留在旧版本。

这是可以存储真实音频、隔离体验身份并交换声音的本机试用产品。没有伪装真人种子用户、AI 代替他人回应或公开社区部署。测试身份与音频明确标注，双角色演示中的两个身份都由同一体验者操作。

## 已实现的产品流程

| 环节 | 行为与规则 |
| --- | --- |
| 留下声音 | 手动开始麦克风录音；结束、离开页面或接近 30 秒时停止麦克风；先本机试听。可导入 1–30 秒、6 MB 内的 WAV / WebM / OGG / M4A 文件 |
| 表达 | 昵称、声音标题、选填背景、主动选择的心情与表达意图。界面以文本呈现，不执行用户内容 |
| 去向 | 只种在自己的花园，或明确同意后投放。未提交录音只在页面内存；保存失败保留草稿，同一提交重试不会重复入库 |
| 接收 | 服务随机分配另一身份的待投放声音；排除自己的声音与已经跳过的声音。一次仅一位接收者，15 分钟未回应的认领可以释放 |
| 倾听 | 原音频播放完才开启回应；服务校验身份、认领、倾听状态及最早倾听时间。也可以跳过或举报 |
| 共生 | 一次有效回应生成共同植物；双方可以重听原声与回应，保留各自昵称及来源 |
| 共同创作 | 顺序播放双方原声，搭配原创雨声、风声或钟声与背景音量。搭配设置持久保存，原录音不会被混音覆盖 |
| 持续关系 | 双方各自主动表达继续交流意愿后，开放后续声音留言；任一方收回意愿后暂停新留言。每次相遇最多 20 段回应 |
| 收回 | 作者可以收回自己的原声或回应；对方的新请求无法获取该音频及正文，作者仍能下载原声，并可重新开放主动收回的内容 |
| 内容处理 | 举报先暂停声音开放，并暂停相关后续交流。服务保存举报；本机管理员可审查并恢复或停止开放，保留处理记录。举报者不会被再次分配同一段声音 |

真实人声保留原意，环境声作为可以共同设计的配合。当前“一起听”是原声按时间顺序播放加声景，没有导出混音、多人实时录音或 AI 声音生成。

## 实际运行

在仓库根目录运行：

```powershell
python projects/004-rhythm-drop/server/drift_server.py
```

打开 http://127.0.0.1:8941/garden/drift/ 。服务默认只绑定本机 127.0.0.1；旧故事、种植版、生态版继续在 8940，原页面与档案键未修改。新服务也提供静态页面，但回声页的历史版本链接返回 8940，以保留原地址下的浏览器档案。

界面右上角“本机身份”支持新建、改昵称与切换最多八个体验身份。用作者身份投放，切到倾听者接收并回应，再切回作者即可验证相遇。不同浏览器也可以各自创建身份并连接同一台本机服务。匿名身份使用随机凭据与服务端哈希；音频只能由作者及获得授权的相遇参与者请求。

麦克风需要用户在浏览器授权。当前内置浏览器出现过未开放麦克风的状态，文件导入路径已实际验证，不宣称真人麦克风录制已验收。

## 存储、恢复与研究保留

- 数据库：`build/drift/community.sqlite3`，包含匿名身份、音频原文件、漂流状态、相遇、交流意愿、声景、举报和提交编号。SQLite 事务保存，重启恢复；不是云备份。
- 浏览器身份入口：`rhythm-drop.echo.identities.v1`。清理浏览器数据会丢失身份入口，当前没有账号找回或跨设备迁移；旧版本键独立保留。
- 原声音有下载按钮；没有整座花园混音导出。清空页面草稿不会删除已经保存的声音。
- 每身份每天最多 30 段录音，同时漂流最多 10 段；请求限制及服务端音频大小、签名校验。WAV 服务端校验实际时长，其余类型由浏览器解码校验时长并由服务端校验容器签名，不等同于生产转码服务。
- 研究 ZIP 保存源码、文档、测试和截图，忽略 `build/`，因此不包含声音数据库、浏览器凭据或私人录音。备份业务数据应在服务停止后单独保存数据库；当前没有自动业务备份。
- GitHub Pages 的静态打包保留新页面及旧版本；静态托管不会运行 Python API，页面会提示社区服务未连接。

## 本机管理员处理入口

```powershell
python projects/004-rhythm-drop/server/drift_server.py --reports
python projects/004-rhythm-drop/server/drift_server.py --resolve "举报编号" --decision restore
python projects/004-rhythm-drop/server/drift_server.py --resolve "举报编号" --decision withdraw
```

处理入口仅为本机命令，没有网络管理员 API。`withdraw` 停止对外开放，作者不能自行重新开放管理员停止的内容，但可以取回自己的原文件。没有声称存在后台人工运营团队。

## 下一步的产品验证

邀请少量真实参与者验证三件事：能否听出声音背后的具体处境；回应是否有意义；是否愿意再次表达或继续这次相遇。记录声音被接收、完整倾听、首次回应、双方愿意与后续留言的转化；当前数据库状态能支撑这些观察，未实现运营分析面板。

公开社区需要另外完成部署与 HTTPS、可恢复账号、音频转码与完整校验、业务备份、举报运营与内容规则，以及真实用户试用。本轮完成本机产品闭环，没有把这些后续工作表述为已经上线。
