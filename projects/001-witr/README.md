## 核心结论

witr 是 Go 编写的系统诊断 CLI / TUI。它将多种查询目标转换为进程或容器信息，读取当前进程关系和上下文，再用规则解释启动来源。

- **能力**：进程、端口、文件持有者、容器查询；祖先进程链；工作目录、Git、服务和资源信息；文本、树和 JSON 输出。
- **原理**：平台专用采集器 + 公共数据模型 + 父进程追溯 + 来源识别规则 + 输出层。
- **效果**：将“端口被 PID 4821 占用”推进为“这个进程由哪个终端或服务启动，属于什么目录”。
- **扩展**：优先在外部调用 JSON；需要专有启动器时再改来源识别与采集代码。核心在 `internal/`，不是已经稳定开放的诊断 SDK。
- **对本地开发的价值**：排查端口冲突、残留服务器、文件占用，判断应该处理哪个项目或服务。

## 采用判断与运行方式

底层查询能力大多已经存在于系统接口、系统命令和其他库中。witr 的主要增量是采集适配、信息关联、来源规则和统一交互。对于已经有成熟采集工具链的使用者，新增底层能力有限；可以将其作为日常排障工具和跨平台实现参考，降低作为独特技术储备的研究优先级。

原生展现方式是终端 CLI 报告和 TUI 交互面板；JSON 是程序集成输出。支持 Linux、Windows、macOS、FreeBSD。这个子项目的网页是教学模拟；要显示真实数据，需要自行增加本地后端调用 witr，再把 JSON 交给网页。HTTP / MCP、持续历史采集、持久化与告警属于扩展方向，不应当作上游已经提供的完整能力。

## 本地运行

在仓库根目录运行（Python 3.10+，无需第三方依赖）：

```powershell
python -m http.server 8937 --bind 127.0.0.1 --directory projects/001-witr/web
```

浏览器访问 `http://127.0.0.1:8937/`。如端口被其他项目占用，可更换端口；结束演示时在启动终端按 Ctrl+C。

```text
witr --port 3000
witr --pid 6100 --tree
witr --pid 4821 --json
witr --container redis
witr node
witr --port 9999
```

最后两个示例分别展示多个匹配、示例中未找到结果。文件路径随平台变化，点击“文件占用”自动填入。

## 验证与局限

- 已检查网页脚本语法，并进行浏览器交互验证；详细记录见 [验证记录](notes/validation.md)。
- 原理结论来自固定版本源码与 README；不声称四平台实际运行或性能基准已经完成。
- 当前链条不等于完整历史；读取失败和父进程退出会影响追溯。
- Windows 的文件查询与系统锁列表是两种不同能力；前者支持，后者不支持。
- Linux / Windows 的基础 CPU 指标采用生命周期平均口径，不能直接当作瞬时负载。
