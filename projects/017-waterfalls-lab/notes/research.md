## 求解器

`src/shaders.js` 的 `SIM` 包含四个计算入口：

1. `prepare`：施加重力、处理出水与开放边界回收，流量为零时允许离域粒子休眠。
2. `p2g`：向 3 × 3 × 3 邻域传递二次 B 样条权重、质量、动量和体积。
3. `updateGrid`：定点原子累加转换为网格位移，处理地形及障碍碰撞。
4. `g2p`：回传粒子位移与 APIC 仿射矩阵，计算体积约束修正；最后一轮积分位置与体积比。

每个粒子 80 字节：位置 xyz 与体积比 J、每步位移 xyz 与泡沫强度、仿射矩阵 C 的三个 vec4 列。网格 `52 × 56 × 44`，单元宽度 `0.24`。节点使用整数原子累加，在 WGSL 缺少浮点原子时汇聚数据。

固定 `dt = 1/120 s`，C 表示每步位移梯度。液体体积约束的各向同性修正近似为：

```text
alpha = (1/J - tr(C) - 1) / 3
C' = C + alpha * I
```

实际应用松弛系数、限幅和少量黏性以适应有限迭代。粒子体积随数量按 16,384/count 缩放，光学半径按对应立方根缩放，减少画质切换时水量与厚度变化。挖穿底部的水可经开放边界回收，源位置和高度可以编辑。每步 3 次约束迭代，最终更新 J；J 限制在 0.3–2.5。稀疏节点采用更多弹道运动，减少孤立飞溅被冻结。该视觉近似不能用于严格不可压缩性或工程精度的论证。

V2 的三维标量场以网格单位存储，初始值为高度场的 y-h。球形笔刷通过 min / max 执行堆筑与挖掘，恢复笔刷在范围内写回原始场。该场是用于碰撞的距离近似，并非精确欧氏有符号距离场。旋转椭球对象预先合并进同一场，GPU 每次只采样三维场，不再逐件循环，去掉原先 16 件上限。三线性采样和中心差分梯度处理网格位移与粒子表面投影，增加碰撞泡沫。岩石不模拟动态刚体。

## GPU 调度

每帧按墙钟时间累积子步，每帧最多 4 步以限制负载。12 份独立计算 uniform 对应 4 步 × 3 次迭代，避免一次提交中多次写同一 uniform 导致 dispatch 读取最终参数。

每步先 prepare，再重复清空网格、P2G、网格碰撞、G2P。渲染在计算后提交。`queue.onSubmittedWorkDone()` 完成后才排下一帧，避免持续堆积 GPU 工作，显示实际完成帧率。低性能设备可能在最大子步限制下以较慢物理时间推进。

未雕刻的初始场景直接生成几何；雕刻后用工作线程执行 marching tetrahedra 并让植被根据新表面高度重新落位。任务带版本号，只显示最新版本；工作线程繁忙时只保留下一份最新任务，避免连续雕刻积压。碰撞场先在 CPU 更新并上传，视觉网格稍后完成；界面显示“正在雕刻”，截图等待网格与碰撞版本一致。对象几何单独重建并更新阴影。质量切换销毁旧模拟缓冲，resize 销毁并重建渲染目标。

## 渲染管线

```text
PB-MPM 粒子状态
    ↓
森林 + 岩壁 → 2048 阴影 → 场景颜色与深度
    ↓
水粒子球面深度 + 速度/泡沫 → 双边深度滤波（横 / 纵）
水粒子厚度 → 加法混合
    ↓
逆投影重建法线 → 折射 + 指数吸收 + 菲涅耳反射 + 高光 + 泡沫
    ↓
ACES 色调映射 → 当前画布 / PNG 读取纹理
```

水面直接使用物理粒子，球面 billboard 提供表面深度。两次双边滤波各采样 13 点；厚度按粒子球截面积累加；场景深度负责遮挡。泡沫由速度与碰撞量产生，没有独立气泡流体。

森林、岩壁、花、草与树冠全部程序生成，有几何法线和方向光 PCF 阴影。Three.js 只负责矩阵、相机、射线及 OrbitControls，渲染没有依赖 Three.js renderer。

## 交互与导出

放置和雕刻使用相机射线沿三维场步进与二分求交。移动通过屏幕投影选择物体，在与物体中心同高的平面拖动，Shift 拖动升降。对象支持三轴缩放和 y 轴旋转。历史深拷贝场景、笔刷、对象与水源，记录最近 60 次操作并支持重做。自动保存与命名作品采用本地存储；作品 JSON 包含设计、设置与相机，通过严格范围校验后整体载入。

导出重新渲染到可读取 GPU 纹理，用按 256 字节对齐的行缓冲读取，去除填充，处理 BGRA / RGBA，转为 PNG。预览与下载来自同一实际生成的 PNG。

水声由 Web Audio 本地生成噪声和滤波，不使用外部音频。后台页面静音。

## 排查与结论

- WGSL 整数坐标显式转为浮点 vec3。
- 阴影采样使用 `textureSampleCompareLevel`，避免非一致控制流的隐式导数限制。
- 自动管线布局移除未使用 binding，滤波组只绑定真实使用的资源。
- 主相机与阴影相机统一使用 WebGPU 0–1 深度约定。
- 移动工具改为屏幕投影半径与 24 px 最小选择区域。
- 高分辨率上限同时缩放宽高，保持纵横比。

可复用部分是求解器、屏幕空间渲染管线和可碰撞造景工具。V2 已实现三维体素编辑和作品持久化。当前域仍为固定大小，体素间距 0.24 m；自由物理刚体与更逼真的环境渲染仍可继续扩展。实际验证数据见 [validation.md](validation.md)。


## V3 扩展 · 2026-10-03

多水源数据独立放入只读 GPU storage buffer，每个源使用两个 vec4：网格位置与累计流量权重、每步喷射位移与半径。CPU 按启用状态和独立流量建立累计分布；prepare 回收粒子时按累计分布选择源，在垂直于喷射方向的圆盘内均匀采样，再赋予方向位移。总出水量仍受全局流量调节。缓冲容量按 2 的幂增长，扩容时重建计算绑定；改变参数不重置整个模拟。关闭所有源时回收粒子进入休眠，权重归零而不产生 NaN。当前总粒子数固定，增加水源会分摊这些粒子，极小流量的源受采样数量影响。

平滑从笔刷之前的场副本读取六邻域平均值，用径向衰减与强度混合；不会边写边读而产生扫描方向偏差。削平朝 (y-level)/DX 混合，每个拖动笔画固定起笔高度。二者只改变局部体素，并继续走同一 Worker 网格重建、碰撞上传与历史系统。镜像笔刷沿 x=0 反射中心，中心附近避免重复操作。SVG 范围环根据拾取表面法线和相机投影更新。

编辑工具保留 OrbitControls 的右键旋转、中键平移、滚轮与双指缩放；Alt 临时用左键旋转。对象和水源提供数值坐标，聚焦保持观察方向并根据目标大小拉近。触屏起笔延迟 120 ms，第二根手指到来时取消待执行笔刷。撤销快照同时保存作品名称，避免示例操作使原作品名称丢失。

水面提供三组吸收与颜色参数，泡沫改用随时间连续平移的波纹调制，降低逐帧随机闪烁。折射采样先比较该像素场景深度与水深度，遇到水面前方的物体时回退到未偏移背景颜色，减少前景物体被错误卷入水中的现象。仍使用粒子深度重建表面，没有添加流体表面网格或独立泡沫粒子。

作品格式保持 version 2；新增字段缺省时补默认单水源参数，旧 localStorage 键继续使用。新增水源、外观、平滑与削平都会通过校验并往返保存。导入水源最多 256 处，是文件资源保护，界面没有旧物体 16 件上限。固定模拟域与网格分辨率没有改变。


## V4 · 增量编辑、弹道瞄准与作品历史 · 2026-10-03

`TerrainFieldCache` 缓存原始体素场、当前场与每条笔刷的序列化签名。历史完全保留旧前缀时，仅应用新增后缀；缩短、改写或换预设时从原始地形重新回放。恢复与平滑继续使用原始场和本次操作之前的副本，结果与全量构建逐点一致。CPU 和 Worker 各有自己的缓存，Worker 即使合并中间任务，下一份完整记录也会应用所有遗漏笔刷。网格提取与植被重建没有增量化。

`aimJet` 使用固定速度在恒定重力下的低抛物线解：水平距离 r、高差 h、速度 v 的判别式为 v⁴-g(gr²+2hv²)。不可达时返回空值，保持原水源配置。`traceJet` 绘制空中质点抛物线，用细分段检查当前碰撞场，首次命中后二分定位；越出模拟域即终止。源在固体中或关闭时单独提示。轨迹不模拟出水口宽度、已有水体、黏性和压力，所以它是方向操作辅助，不能保证实际水流逐点经过目标。

普通造景历史仍只保存设计字段。替换整份作品、示例、预设与重置使用完整快照，保存全场景设置、名称与相机；撤销时重新配置 GPU 粒子及渲染尺寸，重做采用同样范围的反向快照。无效导入在校验阶段拒绝，不创建替换快照，也不改变当前作品。

本轮没有修改求解器或水面 WGSL。自动检查与性能对比见验证记录。浏览器运行环境初始化失败，新增界面尚未实机复核，不把 V3 截图当作 V4 证据。


## V5 · 连续笔画与绘制调度 · 2026-10-03

`BrushStroke` 按空间距离采样，保持上个输入点与未用完的间距，避免鼠标事件数量改变同一路径的笔刷密度。每隔半径的 23% 插入位置并插值归一化表面法线；命中丢失时重置连续性，单次跳跃超过 64 个间距只落下一笔，避免生成横跨山谷的连接。app 持续收集样本，约每 45 ms 或积累到 64 点时整批生成 CSG 编辑并更新一次碰撞 / 网格；释放指针、切换工具、临时旋转与撤销前冲刷待执行样本。整个拖动只在起笔创建一个历史快照。削平高度在整笔内固定，镜像每点独立生成记录。

`SourceUploadCache` 比较所有源的实际配置，缓存累计权重、喷射位置与速度；全局流量不改变分配比例，仅改变 uniform 的总出水量。GPU 资源重置强制打包上传。配置未改变时不再重复创建 Float32 源缓冲或提交相同 GPU 上传。比较源配置仍有 JSON 序列化开销，没有声称完全零分配。

模拟 4 子步 × 3 迭代继续使用独立 GPU uniform，CPU 的 12 个 ArrayBuffer / typed array 也复用，不再逐迭代重建。参数布局、数值换算与原写法逐字节一致。CPU 命令测试使用当前实际引擎方法记录 writeBuffer、dispatch 与纹理绑定，不运行 WGSL。

水面柔化复用原双边滤波着色器：首轮 water→blur→smooth，后续 smooth→blur→smooth，每轮横 / 纵各一个 pass。每个 pass 的输入输出不同，不引入纹理读写冲突；合成始终读取最后的 smooth。界面允许 1–3 轮，旧文件缺省为 1、新建默认 2，控制不重置模拟。多轮会增加绘制开销，视觉改善幅度尚待实机复核。


## V6：造景编辑的精度与操作成本

旧拾取按屏幕上的中心距离和最大缩放半径判断，容易选中旋转后的空白区域或重叠物体。现在先用包含岩石粗糙表面与苔帽的包围盒筛选，再按 `buildWorld(..., objectsOnly=true)` 的实际双面三角形取最近相交；体素地形的首次命中限制射线范围。按需缓存几何，变换失效、对象删除清理。装饰植被和水面没有参与遮挡测试，菜单可继续选取被地形遮挡的物体。

移动使用起笔交点与原对象位置的差值，固定本段移动面，消除把对象中心直接放到指针下的跳变。Shift 改变模式时重新建立起点。接近水平的射线使用相机方向的备用移动面，避免水平面无交点或共面交点退化。方向限定与位移吸附在 CPU 计算，保留未编辑轴和原有坐标偏移；触屏可在面板选择 Y 升降。只在第一次实际位移时记录撤销，最终指针样本与待提交更新在结束时立即处理。

镜像沿 x=0：对象位置 x 与 y 轴旋转取反，源位置 x 与水平 yaw 取反，pitch、speed、power、enabled 保留。碰撞场的椭球镜像与喷射方向反射均有数值验证；不声称粗糙岩石三角形逐顶点完全镜像。

对象 GPU 网格缓存按场景、全部对象与选取状态失效，未变的造景不因雕刻或重复选取重新分配 buffer。拖动碰撞更新按 32 ms 合并，最后立即刷新，数值和滑块继续即时更新。本轮没有 GPU 帧率对比。五项应用事件测试使用 DOM / GPU 替身执行真实 `app.js`，检查历史、最终位置、作品切换、镜像快捷复制和触屏事件；浏览器环境故障使新视觉与实机验证仍待补。


## V7：分组操作与保存时机

`ObjectSelection` 以 ID 集合和活动 ID 管理选择，每次读取会清理已删除 ID，避免数组删项后索引错位。GPU 选择标记支持索引数组，以 Set 查询所有对象；缓存键继续包含选择。选择不进入作品格式。多选隐藏只针对单件的尺寸 / 坐标控件，保留位移方向、吸附和批量操作。

`ObjectGroupDrag` 复用位移计算，以所选全部中心位置推导共同位移范围；任何成员到达边界时限制整组，既有间距不变。已有导入坐标可能超出编辑控件范围，范围允许零位移，不会单击就跳位或继续向外偏移。模式切换沿用重设起点，所有成员应用统一位移。复制采用共同偏移、优先向内部；镜像仍按世界 x=0。贴地则对每件独立查询表面并限制高度。聚焦球包围旋转岩石及苔帽。

追加选择下，新对象点选即添加；已选对象点按可移除、拖动直接移动整组。另记指针移动超过 4 px 的意图，避免方向限制 / 边界导致零位移时误当点按移除。取消或页面切走不执行点按移除。首次实际位移才建立历史；每次批量复制、镜像、贴地或删除只建一个快照。

原自动保存 650 ms 的合并窗口在快速刷新时可能丢最后操作；现在 visibilitychange(hidden) / pagehide 同步结束手势、清理触屏起笔并保存最新状态与相机。ready 状态以外不写入，避免初始化失败覆盖旧作品；setItem 抛出时保留旧值并显示失败，之后可重试。系统强制关闭未必派发事件，仍鼓励命名保存或文件导出。导出时的名称也进入自动保存，后续修改隐藏过期下载链接；输入控件的快捷键交由浏览器处理。

将现有文件容量提取为共用常量，新增 / 复制 / 水源 / 笔刷与导入一致，防止 UI 产生无法重开的作品。本轮没有提高文件容量、扩大体素域或假定硬件帧率改善。新增十四项检查均通过，包括实际 app 生命周期事件和实际引擎选择颜色；DOM / GPU 为替身，浏览器进程退出使布局与实机验证待补。

## V8：增量对象编辑

此前每次拖动刷新都会合并全部对象的椭球，并销毁、生成和分配全部对象网格。`ObjectFieldCache` 缓存地形与未编辑对象的合并场，结果数组复用，每次只重新应用活动对象。静态签名包含对象碰撞变换；移动组改变、删除或静态对象变换会使缓存失效。地形数组原地编辑不能只靠引用判断，`TerrainFieldCache.revision` 在真实编辑或重建时递增，未变化的更新保持版本。

`ObjectMeshCache` 保存对象布局、顶点偏移和随机种子。原始对象列表共享一条线性同余随机流，每个椭球单元消耗三次颜色采样；从各对象起始种子生成局部网格，可保留原有逐面颜色。对象几何或选取状态变化只上传对应范围，相邻变化合并成一次上传；GPU buffer 使用 VERTEX | COPY_DST。布局变化才销毁旧 buffer。完整生成与局部更新的 Float32 数据逐项一致，场景与阴影继续绘制这份 buffer。

对象拖动、单件尺寸 / 高度 / 旋转 / 精确坐标和批量贴地把活动索引传给碰撞更新。更新期间意外发生的静态变换仍通过签名失效正确处理。重置模拟创建新 solid buffer 时直接写入缓存结果，不因缓存未变化而跳过新资源初始化。

本轮九项新增检查，加上既有检查的增量上传与组编辑断言，共 67 项 Node、14 项 Python 通过。单次独立 Node CPU 测量：300 件对象中编辑 3 件、40 次更新，4318.18 ms → 71.96 ms；顶点待上传字节减少 98.93%，全部碰撞、顶点和颜色一致。这个样例不能换算为浏览器 FPS，真实 GPU 写入、布局与指针验证仍因浏览器初始化故障待补。模拟 / 渲染 WGSL、文件 version 2 和用户浏览器存储未改动。
