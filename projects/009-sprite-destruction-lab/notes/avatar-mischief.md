# 头像出逃：让角色与真实网页发生关系

这个演示回答的是一个具体问题：头像中的角色能不能跳出圆框，在网页上跑动、踢碎内容，再回到头像里？当前实现可以完成这条互动。它把角色动作接到了已有的 `DestructionEngine` 上，破坏对象是当前主页里的真实卡片。

预览入口：[头像出逃演示](http://127.0.0.1:8949/projects/009-sprite-destruction-lab/avatar/)。源文件为 [页面](../web/avatar/index.html)、[动作编排](../web/avatar/app.js)、[角色绘制](../web/avatar/character.js) 和 [效果引擎](../web/engine.js)。

## 怎么试

1. 点击「让他跳出来」。阿栗从头像位置跳出，落到主页上，跑向第一张卡片，然后踢一次。
2. 等动作结束，点击「去捣乱」。角色会继续跑向还有完整碎片的卡片；目标在三张卡片之间轮换。
3. 点击「叫他回来」。角色跳回头像圆框，已经散开的碎片继续留在页面里。
4. 点击「复原页面」。物理场景和动画场景重置，原来的网页 DOM 恢复显示和交互。
5. 在角色回到头像后，用「换成我的头像」上传 PNG、JPEG 或 WebP 图片，大小不超过 8 MB。再次出发时，上传图片会成为角色的圆形头部。

「显示碰撞边界」显示碎片的物理轮廓；「下载互动记录」导出当前会话里实际发生的动作、目标、命中位置和释放碎片数量。记录来自运行时事件，不是预先编写的剧情说明。

## 哪些部分复用了效果引擎

页面中的三张文章卡片带有 `data-destructible` 标记，目标分别是 `first`、`second`、`third`。`DestructionEngine.prepare()` 读取卡片的实际 DOM 几何位置，并用 html2canvas 将当前主页渲染成纹理。因此，文字、颜色、边框和卡片布局来自正在展示的网页。

当前演示选择 `glass` 模式。每张卡片对应一组玻璃三角碎片，纹理随碎片绘制。碎片最初固定在原来的位置；角色踢中后，命中范围内的碎片解除固定，获得初速度和旋转速度，再由 Matter.js 计算重力、落下、旋转和碰撞。一次踢腿释放的是局部碎片，未命中的部分仍留在原处。

角色的脚到达踢击姿态时，动作代码计算脚尖在场景中的坐标，调用新增的 `impactAt()` 接口。命中、碎片释放、物理更新、效果和统计都继续走同一个引擎生命周期。

准备完成后，实际 DOM 保持原有布局但暂时设为不可见和 `inert`，由引擎画布展示截图与碎片。复原会销毁物理实例、清空效果画布，再恢复原 DOM 的可见性与交互。这种方式让卡片能碎开，也保留了原页面的恢复路径。

## 角色部分是怎样做的

阿栗绘制在独立的 Canvas 层上。头像的出发点与返回点取自 `[data-avatar-home]` 元素的 `getBoundingClientRect()`，再转换成相对于 `#scene-source` 的坐标。头像在手机上变小或页面布局改变后，角色位置会随实际 DOM 重新测量。

角色在头像内时，绘制受到圆形裁切；跳出时扩大裁切范围，离开圆框后展示全身。跳跃、跑动、踢腿和返回通过时间插值、路线和手脚姿态编排完成。`onFrame` 将角色更新接入引擎的帧循环，让脚尖触发时机和碎片模拟共享时间。

这部分是新增的动画与行为代码。它没有使用 AI 生成动作，也没有把角色身体作为真实刚体交给 Matter.js。当前由物理引擎计算的是卡片碎片；角色的位置、姿态和行动路线由程序控制。

## 为外部角色开放的接口

`DestructionEngine` 新增以下构造选项，默认值保留原实验室的交互方式：

| 选项 | 默认值 | 当前头像演示的用途 |
| --- | --- | --- |
| `interactive` | `true` | 设置为 `false`，关闭原引擎对鼠标和键盘的输入绑定，由角色动作主动触发破坏。 |
| `onFrame` | `null` | 每帧收到 `{ engine, elapsed, time }`；`elapsed` 为秒。头像演示用它推进动作并绘制角色。 |
| `showAim` | `true` | 设置为 `false`，隐藏原来的瞄准标记。 |
| `showPlayer` | `true` | 设置为 `false`，隐藏原来的玩家绘制。该选项本身不移除玩家刚体；头像演示在准备后另外移除该刚体。 |

核心连接点是：

```js
const hit = engine.impactAt(
  { x: footX, y: footY },
  { radius: 92, strength: 1.5, weapon: 'blast' }
);
```

`x`、`y` 是相对于源场景的 CSS 像素坐标，和卡片测量结果使用同一个坐标系，不是屏幕坐标或高分屏 Canvas 像素。`radius` 控制命中范围，`strength` 控制释放碎片的速度倍率，`weapon` 可取 `pulse`、`scatter` 或 `blast`。

该方法默认使用 `radius: 75`、`strength: 1`、`weapon: 'blast'`。引擎限制半径为 8–300、强度为 0.1–3，并将命中中心约束在场景内。只有运行状态接受命中，连续调用有 100 毫秒间隔限制。返回值表示这次调用是否命中了尚未释放的碎片；命中时会沿用原有的互动事件与统计。

一个最小的接入形态如下，`updateActor` 由接入方实现：

```js
const engine = new DestructionEngine({
  canvas: engineCanvas,
  source: sceneSource,
  effect: 'glass',
  interactive: false,
  showAim: false,
  showPlayer: false,
  onFrame: ({ elapsed }) => updateActor(elapsed)
});
await engine.prepare();
engine.start();
```

## 能带来什么产品价值

它可以把头像从静态识别图变成有动作、会与页面内容发生关系的角色。独立创作者主页、品牌活动页或作品展示页可以用一次明确的互动留下记忆：角色从哪里来、对哪张内容动了手、最后回到哪里。

这里的产品价值来自角色行动与真实内容之间的联系。角色换成品牌形象、卡片换成活动任务后，同一个连接方式可以支持一个简短互动；内容也可以先被打散，再通过复原重新呈现。是否使用破坏效果，应由页面目的决定。

## 可继续扩展的方向

以下方向尚未在当前演示中实现：

| 方向 | 可以接着做什么 | 需要补充的能力 |
| --- | --- | --- |
| 跟随人物 | 角色跟随指针、停靠页面边缘，或跑向用户正在浏览的内容。 | 指针与滚动监听、路径规则、遮挡和边界处理。 |
| 拖拽角色 | 用户把角色从头像中拖出来，放到某张卡片旁，再触发动作。 | Pointer Events、拖拽状态、坐标转换和手势处理。 |
| 品牌形象 | 为品牌角色设计专属外形、动作、声音和触发剧情。 | 专门的角色资源与动作系统；现有示例仅提供原创向量角色和静态头像头部替换。 |
| 页面引导 | 角色跑到某个功能旁，指向内容、揭开提示，完成引导后回到头像。 | 引导状态、目标选择、提示层与流程规则；无需每一步都破坏内容。 |
| 真实角色物理 | 让角色身体与地面、卡片和碎片相互碰撞。 | 角色碰撞体、关节或布娃娃模型、运动控制与视觉姿态同步。 |

## 当前边界

- 上传头像只替换静态圆形头部，头部仍附着在程序绘制的身体上。演示没有自动抠出照片里的人物、生成全身、建立骨骼或生成新动作。
- 当前活动范围是本页的主页场景和其中三张卡片。它没有安装到任意网页，也没有扫描其他网站来自动选择可破坏对象。
- 卡片内容先被截图成纹理；破坏阶段不是可编辑的实时 DOM。窗口尺寸变化时会复原场景，让下次出发使用新的实际布局。
- 角色行为采用预设路线与状态，当前没有语言理解、自主规划或聊天能力。
- 没有确认原作 `destroy.spritefusion.com` 提供公开 SDK。这里是在本地独立 `DestructionEngine` 上增加角色互动，不宣称调用或复用了原作的私有程序。

## 运行证据

验证结果保存于 [avatar-checks.json](avatar-checks.json)：18 项真实浏览器检查通过，覆盖跳出、实际碎裂、召回、上传、导出与手机操作。引擎与数据测试 28 项、原实验室浏览器回归 21 项通过。完整动作的截图为 [头像内](../assets/avatar/home.png)、[跳出](../assets/avatar/escape.png)、[踢击](../assets/avatar/kick.png)、[继续捣乱](../assets/avatar/mischief.png) 和 [返回头像](../assets/avatar/returned.png)。

这些材料用于核对页面位置、角色状态、命中和碎片变化。具体动作与释放数量可在验证记录和实际事件文件中核对。
