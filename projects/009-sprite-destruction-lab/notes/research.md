## 客户端核对的流程

1. 静态 HTML 来自 /api/page?url=…，读取 x-final-url 响应头。
2. 脚本路径为 /p/{protocol}/{host}{pathname}{search}，受限 iframe 配置包含 allow-scripts，采集用 postMessage。
3. 脚本路径失败时有静态路径分支；不保证每个页面加载成功。
4. DOM 遍历使用 getBoundingClientRect、getComputedStyle、Range 等读取矩形、样式、文字；不同媒体有独立处理。
5. 存在 glyphs、paints 等采集结果，进入关卡生成，不等同于本地纹理图像方案。
6. URLSearchParams 读取 url 与 room，支持网址和房间链接。
7. 房间创建 /mp/new，WebSocket /mp/{room}/ws；有上传、下载和 gzip 解压关卡的路径。

未检查服务端源码，不能推断完整代理规则、联机时钟、服务器权威算法或运行成本。

## 本地实现

html2canvas 1.4.1 按 DOM 和支持的样式重建图像，Matter.js 0.20.0 求解二维刚体。锁文件、本地 vendor 和完整许可，使三个场景不依赖外部账号与 CDN。

标记区域按网格拆分，每片持有原始图像坐标与 Matter body；Canvas 按 body.position 与 body.angle 逐帧绘制。底图先清除可破坏区域，避免残留原内容。

Matter.Query.ray 寻找未破坏块的最近命中。射线避免高速弹丸离散帧穿透，但不模拟真实子弹弹道或材质穿透。散射用多条射线，爆破扩大受击半径；碎片、页面块、角色和地面参与刚体求解。

### 实际物理修复

初次测试发现：直接构造 isStatic:true 的可释放碎片，解除固定后质量与惯量无法正确恢复，可能产生非有限坐标。改为先创建动态矩形，再 Body.setStatic(true)，让有限动态属性被保留。

4 项测试包含解除固定后真实下落并停在地面的验证；浏览器也验证全部释放碎片的坐标和惯量有限。仅检查 UI 进度无法发现这一问题。

任务使用原始面积，边缘小块不与完整块等权。旧价标签单独计算，全局与目标进度分开。complete 只触发一次；复原销毁物理、动画和监听器，尺寸变化回到 DOM。

## 场景价值与扩展

研究首页用真实清单和项目入口。活动内容为自建示例，但命中、解锁、剪贴板和日志实际执行；未接入订单或核销。课堂参数即时求解，适合解释运动而非精密测量。

低成本：自有 DOM、文字、标签、阈值、重力和完成事件。
中成本：多尺寸与 CSS 适配、素材许可、字体、音效、细粒度碎裂、大量刚体优化。
高成本：第三方采集后端、受限执行、缓存和兼容性；多人状态、房间和重连；营销发放与核销。

新增价值是内容、运动、任务和业务动作分离，未创造新的物理底层能力。当前无线上流量、留存或收入验证。
