# 从画面需求到代码动效

日期：2026-10-02。对应 [本地实验室](../web/workshop.html)。这是一组独立编写的教学扩展，用于演示与试验，未调用或复制 CellMotion 的动效运行时。

## 先按这个顺序操作

1. 换成自己的第一句和第二句。
2. 在文字匹配、逐字打入、放大接力、碎片聚合之间切换，先决定运动方式。
3. 拖动时间轴，查看进场、停留、变化、完整停留。下面的说明和阶段进度算式会同步变化。
4. 修改进场、缓动、逐字间隔、停留、总时长、画幅、字号和颜色；也可选择本地图片替换第二句的一个字位。
5. 到“如何提问”填写用途和交付形式，复制自动生成的需求。可以自己继续编辑文字。
6. 保存配方 JSON，以便复用内容和设置；保存 PNG，作为当前帧的视觉验收参考。

生成需求是规则化的文本生成，没有调用 AI 或自动执行视频制作。图片作为 data URL 存在内存和下载的配方里，不上传服务器。导入配方会恢复素材和参数，但不会保存上次的播放位置。

## 底层计算到底是什么

最小单位是“一帧”。假设一个字要从横坐标 100 移动到 300，匀速移动用下面的计算：

```text
进度 p = (当前时间 − 开始时间) / 持续时间
横坐标 x = 100 + (300 − 100) × p

p = 0.0 → x = 100
p = 0.5 → x = 200
p = 1.0 → x = 300
```

轻缓起止会先把 p 转成 `p × p × (3 − 2 × p)`，再计算位置。弹性回落使用带过冲的 back easing；它是一个缓动函数，没有进行真实物理弹簧模拟。类似的方法可以改变大小、透明度和颜色。

这里用 Canvas 2D 在浏览器中画当前帧：

```text
内容和参数 → 字符/图片单元 → 测量与排版
当前时间 → 当前阶段 → 阶段进度 → 每个单元的状态
单元状态 → 清空画布 → 绘制完整当前帧
```

每次拖动时间轴都会直接重新计算，不依赖“先播放到这里”。碎片效果的随机分布固定种子，因此相同配置和同一时间点能重现同一帧。跨操作系统的字体、emoji 和抗锯齿可能不同；配方没有嵌入字体。

视频是在此基础上增加固定帧率取样与编码。例如 4 秒、30 fps 要按帧号取 120 帧，再送给编码器。Remotion 也采用由帧号驱动画面的方式；它提供 React 场景与视频制作工具。这里是普通 JavaScript + Canvas，不依赖 Remotion。可以将已有 Canvas 绘制函数接入视频渲染流程，但仍需安排资源载入、音轨、分辨率和编码。

## 四种演示改变了哪条规则

| 配方 | 元素模型与计算 | 视觉结果 |
| --- | --- | --- |
| 文字匹配 | 把相同字符配到未占用的目标字位，插值位置；删字缩小，新字增长 | 相同字保留身份并迁移，文案完成交接 |
| 逐字打入 | 计算每个字符的出现时刻、透明度和轻微位移 | 第二句从左到右显现，变化阶段带光标 |
| 放大接力 | 逐字错峰缩放，根据当下宽度重新排布邻字 | 字符依次放大并回落，周围字符让位 |
| 碎片聚合 | 在离屏画布采样文字/图片像素，最多 900 个点；为点计算固定路径 | 文字散为点，聚到目标形状，最后接回清晰文字 |

图片保留原始宽高比例，适应选定字位。长句会缩小以适应画幅；它不是多行自动排版系统。字位按照 grapheme 拆分，组合 emoji 不按 UTF-16 代码单元拆散。辅助框和连线用于看目标字位与字符对应关系，导出 PNG 不包含它们。

## 怎样提出第一个问题

可以不先选择技术，先把画面说清楚。六项是内容、动作、时间、样式、输出和验收。信息暂时不完整时，也可以要求先做少量方案比较。

> 请做一段品牌开场动效：第一句“让创意生长”，第二句“创意自由生长”。第一句从下方进入，停留 0.6 秒；相同的字沿基线移到新字位，删去的字原位缩小，新增的字在目标字位长大。总长 4 秒，最后保持第二句 0.8 秒。横屏 16:9，深绿背景、浅黄文字。先交付可拖动时间轴的网页，开放文案、颜色与时长参数；保证最终文案完整，重播和跳转得到一致画面。

不确定效果时，可以这样驱动比较：

> 用同一组文案做三个可比较的预览：相同字迁移、逐字出现、碎片聚合。比例、颜色和总长一致。每个方案说明阅读感受、适合场景，以及可调参数；我选定后再完善节奏。

## 怎样指导第二轮修改

指出在哪个时刻、哪个元素、希望怎样变化，以及什么应保持一致。

- “1.5 秒左右变句开始得太早，第一句再多停留 0.3 秒，总时长仍保持 4 秒。”
- “保留当前文案和颜色，把弹入幅度减半，结束时不要晃动。”
- “放大的字遮住了邻字，按它的当前宽度调整周围字位。”
- “把第二句第 2 个字换成我提供的图片，保持比例，图片跟这个字位一起移动。”
- “先在 16:9 验证，再增加 9:16；内容不裁切，文字自动适应画布。”

反馈后的制作循环是：修改配置或运动规则 → 按指定时间画预览 → 对照验收条件 → 保存版本。保存 JSON 方便下一次沿着同一方案继续修改。

## 扩展到什么程度，补什么模块

| 层次 | 你可以怎么要求 | 实现工作 |
| --- | --- | --- |
| 参数 | “把文字、颜色、节奏开放成模板参数” | 增加字段、验证、控件和保存逻辑 |
| 组合 | “先弹入，再换句，最后保持” | 增加阶段、明确先后与持续时间，协调前后状态 |
| 算法 | “字符沿弧线飞入”或“文字散为碎片再聚合” | 增加元素模型、路径或模拟，以及逐帧绘制规则 |
| 产品流程 | “读取 CSV，批量导出 100 个视频” | 数据字段、素材处理、渲染任务、编码、命名与失败恢复 |

音乐响应需要音频特征和节拍映射；多段长片需要场景时间轴、转场、音轨；3D、液体和真实物理需要对应的几何、材质、模拟与渲染算法。它们可以继续开发，尚未在本实验室实现。
