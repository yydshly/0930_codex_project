# 业务交互交付约定

按任务规模填写下面模板，可删掉无关字段。目标是让配置、页面、导出与验收说同一件事；字段名不是必须实现的框架 API。

本项目工作台已经实现任务计划导出：`skill-{mode}-delivery.md` 与 `skill-{mode}-contract.json`，`mode` 为 `story`、`explain`、`territory` 或 `reveal`。JSON 使用 `schemaVersion: "1.0"`，包括项目、用户任务、计划范围、当前业务示例结果、交付物、验收与待测指标。下面输入/状态示例用于新客户项目的适配，不是该导出的精确序列化格式；实际格式以 `web/skills-lab.js` 中 `contract()` 为准。

工作台选择“原型 + 业务接入计划”只扩展计划交付项。项目名称与任务编辑也只修改计划；不会自动生成新页面、接通后端或重写品牌/产品原型。当前示例结果分别来自关联场景的最近配置快照、虚构地区查询或普通提示内存记录。品牌/产品快照按场景保存在本次页面会话内，切换技能与业务场景不丢失；刷新后缓存重建。

## 输入模板

```yaml
task:
  audience: "谁使用，例如：首次查看新品的客户"
  action: "要完成的动作，例如：比较并选定一款桌灯"
  result: "完成后的可见结果，例如：可下载含配色和结构选项的需求单"
  channel: "现有页面/新建本地原型及设备要求"
content:
  brand: "品牌、标题、说明、行动文案"
  options: "产品/套餐/区域/提示条目，含稳定 id"
  rules: "参数范围、单位、服务范围或揭晓条件，注明来源"
assets:
  supplied: "自有图片/视频/模型及本地路径"
  missing: "尚缺素材与可接受的临时方案"
data:
  mode: "真实数据 / 标注的示例数据"
  source: "数据来源、更新时间、允许的用途"
  persistence: "不保存 / 本地保存 / 已授权的后端接口"
delivery:
  files: "运行页面、配置 JSON、需求单；按需 PNG"
  environment: "项目路径、启动方式、现有技术栈"
  external_actions: "用户已授权的真实提交或发布；未授权则保持本地交付"
```

没有规则或接口时，继续完成示例范围内的页面与交付，注明缺口；必须依赖它们的真实判断或外部操作不冒充已完成。

## 内容与状态模板

把稳定业务内容放在配置，用户当前选择放在状态，业务结果用独立字段表示。可按场景删改：

```json
{
  "schemaVersion": "1",
  "scenario": "product-explanation",
  "content": {
    "title": "选择适合你的桌灯",
    "options": [
      {"id": "forest", "label": "山林绿", "asset": "assets/lamp-forest.webp"}
    ],
    "actionLabel": "导出当前配置"
  },
  "selection": {"optionId": "forest", "finish": "matte", "explodePercent": 30},
  "result": {"status": "preview", "submitted": false},
  "provenance": {"dataMode": "example", "source": "本项目示例", "updatedAt": "填写实际日期"}
}
```

这是交付数据的例子；现有五个研究模块不能直接消费此 JSON。实施时定义实际适配函数，并让表单、视觉和导出读取同一状态。对输入做必要的类型、范围、单位和 id 校验。

常见状态选择：

- 产品选择：初始 → 已选择 → 保存/导出；修改后更新当前配置，保留已保存方案供比较。
- 区域查询：等待输入 → 查询中 → 可服务/不可服务/无法判定；定位动画是结果的可视化，不能自行决定业务资格。
- 奖励揭晓：待开始 → 执行中 → 显示结果/失败；本地随机只能作为示例提示。正式奖励需要清楚的资格来源、结果持久化及真实发放接口。

## 输出模板

交付说明应能让接手人复现和继续工作：

```text
业务任务：
实现范围与运行入口：
用户输入 → 可见反馈 → 最终结果：
配置文件与导出文件：
素材/数据来源及替换位置：
本地存储或接口状态：
已完成的验证与证据路径：
当前限制与下一步所需资料：
```

需求单至少包括：客户问题、当前选择与单位、拟交付内容、预期价值、真实数据/接口缺口、验收办法。配置导出至少包括：场景、稳定选项 id、当前参数、版本、来源与示例标记。PNG 只表达画面，不替代结构化参数。

## 验收模板

| 维度 | 可观察的判据 | 证据记录 |
| --- | --- | --- |
| 视觉 | 桌面与手机下标题、主要物体、控制器、结果可见且无相互遮挡；变化前后可辨认 | 实际截图或操作录屏，注明尺寸与状态 |
| 任务 | 用户按入口完成目标；反馈区分被接收、进行中与完成；失败/空结果有下一步 | 一次完整任务步骤与最终状态 |
| 参数与数据 | 参数变化对应画面和文案；规则结果用已知样例核对；单位一致 | 样例输入、预期结果、实际结果 |
| 导出 | 下载内容匹配屏幕真实选择；保存方案与当前方案不会互相覆盖 | 实际导出文件和当前界面截图 |
| 设备与降级 | 键盘/按钮可操作；减少动态偏好、暂停及媒体失败仍可完成核心任务 | 实测环境与结果；模拟和实机分别说明 |
| 生命周期 | 重复切换、重置不会增加旧循环、产生迟到状态或覆盖新选择 | 与实现相称的行为检查；未验证项明确标记 |

业务效果单独约定，避免用“页面已运行”替代效果证据：

```text
价值假设：例如，结构展开有助于客户正确理解两个型号的区别。
待测指标：理解正确率 / 任务完成率 / 有效咨询比例 / 评审往返次数，按任务选取。
测量定义：分子分母、观察时段、参与者与版本，是否有可比基线。
证据状态：未测 / 已采集但不足 / 有记录支持；附数据来源。
允许的结论：先报告观察结果与限制，不把假设写成转化或收入提升承诺。
```
