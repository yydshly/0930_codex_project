# 从目标生成制作要求

入口为 `web/foundry/studio.html`；本次验证产品是 AURA 原创头戴式耳机。用户提供产品与任务，系统整理具体要求；已实现的产品模块负责运行。制作要求与可操作实现分别验收。

## 输入与约束的分工

| 层 | 谁负责 | 当前内容 |
| --- | --- | --- |
| 用户目标 | 用户 | 产品、希望访客完成的任务；受众、优先项、偏好与已有资料可补充 |
| 通用质量要求 | 系统 | 文字与主体可读、手机构图、可操作状态与导出一致、缺失事实不编造、实际运行截图、独立包运行 |
| 产品专属要求 | 制作模型或本地规则 | 根据目标组织材质、镜头、素材、部件与操作。例如耳机需要头梁、耳垫、金属外壳、配色与折叠关系；不继承马桶的坑距规则 |
| 实现与验证 | 产品适配器与制作流程 | 生成或接入素材、实现形体和业务、实际操作、下载并核对内容与画面 |

用户不用填写金属粗糙度或相机参数。模型需要把“质感好、便于选配”转成可观察的制作要求；要求文本本身不是已完成的页面。

## 三种来源

1. **耳机 AI 制作示例**：本次制作中的代理模型制定的方案，预置用于验证完整路径。修改输入后不能继续使用这份方案冒充新结果。
2. **本地规则整理**：`planner.js` 中的封闭分类与任务规则，引用实际输入形成草案。它不是语义模型，不保证理解任意自然语言条件；明确排除项需核对并在制作时落实。
3. **在线模型生成**：`tooling/planning-server.py` 接入 Responses API 的结构化输出。服务端保存 `OPENAI_API_KEY`，可配置 `OPENAI_MODEL`；未配置时关闭在线入口。当前测试包含模拟成功、失败、过期取消与无密钥反馈，尚无真实在线调用验收。

封闭方案契约在 `planning-contract.js`。只接受类型、文本、六位颜色、素材与验收列表，不接受脚本、HTML 或任意模块 URL。前后端分别校验类型、长度与类别。模型方案不得把入耳耳塞或咖啡机归为已实现的头戴耳机。

## 当前真实运行边界

已有头戴耳机、马桶、桌灯三个产品模块。方案进入工作台时携带本次目标、用户、标题、说明与制作要求；形体和系列素材仍来自该已实现模块。制作要求不会自动改写所有镜头、图片或业务逻辑，未覆盖的要求必须进入后续实现与验收。

未知产品可下载制作清单，试用入口保持不可用，明确列出待实现的素材、形体和业务模块。不得换个标题就复用耳机页面声称完成新品生成。

在线生成目前只生成要求数据，不生成任意页面代码、实物 CAD 或浏览器运行时图片。未来扩展应新增产品模块或独立的实现服务，再沿相同数据、预览与交付契约验收。

## 耳机固定验证任务

默认目标为“看清外观、比较材质、选择配色并留下配置”。方案要求：暖色横版主视觉、独立手机竖版、同系列特写、真实配色/材质/折叠/部件操作、两种照明、当前配置与独立包。

- 输入改动后旧方案不能下载或继续试用；在线返回过期结果不得覆盖新目标。
- 更换配色与表面，折叠 0/50/100%，切换部件与环境，检查实际模型与控件。
- 使用键盘改变观察角度和缩放，导出 JSON、Markdown 和 PNG；所选状态和像素必须一致。
- 下载 ZIP，阻断包外资源运行，核对影像、材质、选择和自定义角度恢复。
- 检查 1440/768/390 像素下的布局与手机独立素材；这不等同真机性能测量。
- 无 WebGL 时说明三维不可用，关闭不可用结构操作，保留配置记录。

当前证据见 [验证报告](../../../notes/headphone-verification-v12.json)、[制作记录](../../../notes/headphone-build-v12.md)和 [视觉核对](../../../design-qa.md)。重量、续航、连接与声学性能待厂商提供；没有音频试听、真实订单或商业效果测量。

## V1.4 · 方案调整与交接

方案、素材缺口和调整验收分栏显示。可修改标题、文案、制作要求及其验证方式；已支持模块可选择表面比较和部件展开范围。调整未应用时禁止使用旧交付，应用后记录来源与次数，文案、范围进入实际模块，要求进入方案与独立包。关闭的操作也从交付任务中移除。

Markdown 制作简报与结构化 JSON 分别面向阅读交接与程序处理。列出的验收任务是待执行清单，不是通过证明。要求文本的编辑不会自动制作新形体、影像或业务功能。实际范围、保存、重置与隔离交付证据见 [V1.4 记录](../../../notes/foundry-refinement-v13.md)。
