# 三个业务场景 · 第五版视觉核对

用户指出第四版的质感仍明显弱于原站，并要求处理另外两个场景。此前“功能通过、没有剩余布局问题”的结论不能证明视觉质量达到要求，本轮重新检查素材、材质和构图。

1. 先捕获原站与第四版三个场景：`assets/qa/v5/reference-source.png`、`before-{brand/product/garden}.png`。原站依靠真实食物影像、鲜明字体与完整局部构图；品牌的 CSS 茶罐、产品的简单环境和庭院色块图缺少相应材质层次。
2. 按场景分别制作并接入：品牌的原创生成摄影与实时 HTML 标签；产品的木台、微纹理、生成棚拍全景反射和细金属支柱；庭院的独立参数化几何、选定木石贴图、叶片植物、水面场景反射与日夜灯光。素材和最终提示词在 `scene-assets-v5.json`。
3. 检查桌面、平板和手机实际画面，包含品牌长文案、产品结构/细节、庭院三维/正交平面、极端尺度、夜色和无 WebGL 兼容状态。最终截图为 `assets/qa/v5/final-{brand/product/garden}-{1440/768/390}.png` 等，原始浏览器录像在 `assets/business-scenes-v5.mp4`。

| 发现 | 改动与证据 |
| --- | --- |
| 品牌平面茶罐没有纸、瓷、木材与自然光层次 | 生成概念摄影保留纹理与影调，左侧留出文字空间；包装名和茶款仍由真实业务状态更新。`final-brand-1440.png`、`final-brand-390.png` |
| 产品只有光滑颜色，缺乏环境与材料关系 | 加入真实木纹展示台、涂层微纹理、环境反射和细金属构件；第一轮粗石地面干扰主体，已改为柔和暖色背景。`final-product-1440.png`、`product-night.png` |
| 庭院只有二维色块，无法观察空间与材料 | 改为 WebGL 几何、木石贴图、单叶实例植物、灯光阴影和实时水面。顶视图也由同一模型正交投影。`final-garden-1440.png`、`garden-night.png` |
| 顶视庭院碰到标题与工具栏 | 顶视模式压缩标题、隐藏副文案并调整取景范围；390/768/1440 的平面截图检查通过 |
| 比较说明使侧栏变高，改变画布高度和相机取景 | 固定庭院展示高度；同一查看状态下保存方案 A、调整方案、返回 A 和返回当前方案，实际 Canvas 图像分别一致 |
| 小屏包装文字跑到纸标下方，长标题可能挤占图片 | 修正包装文字位置，按标题/品牌长度缩放文字；长文案三种视口均未溢出或遮住底部 |
| 大尺寸庭院因相机距离增大而被雾化洗淡 | 雾化范围随相机距离调整，保持主体材质清晰；检查 18×14 m 的实际小屏画面 |
| 二维兼容图的底部说明与状态文字碰撞 | 缩短兼容图绘制区，保留底部文字与工具栏空间；检查 garden-fallback-390.png |

持续动效默认遵循减少动态偏好，可主动开关。产品与庭院保留键盘操作、表单参数及明确文本结果；无 WebGL 时明确显示二维兼容画面并停用不支持的操作。图像替代文字、画布说明和区域面积提供辅助信息；没有进行屏幕阅读器或真实手机硬件测试。

本轮 41 项三场景检查、50 项产品检查、48 项业务回归和 39 项技能工作台检查通过，浏览器未处理错误为空。检查实际像素、状态和输出，而非只验证按钮样式。报告分别为 `business-scenes-v5-verification.json`、`product-showcase-verification.json`、`verification.json` 和 `skill-verification.json`。

品牌是 AI 生成的概念摄影，产品和庭院为实时交互概念模型；棚拍全景是生成的 LDR 图像，没有实物、照度或现场标定。本轮已经补齐上一版素材、材质和空间呈现的明显缺口，最终偏好仍由用户判断，检查数量不代表与原站影像质感相同。
