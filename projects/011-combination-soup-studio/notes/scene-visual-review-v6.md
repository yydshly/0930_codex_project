用户指出看不到房间用于产品展示。本轮首先捕获第五版的桌面和手机画面：`assets/qa/v6/before-{brand/product/garden}-{1440/390}.png`。第五版房间只用于材质反射，庭院叶片在总览中也难以观察。

| 实际发现 | 修正与画面证据 |
| --- | --- |
| 房间没有可见背景，素材用途难以理解 | 室内全景作为桌灯默认背景；提供室内/棚拍、环境反射开关和可展开的真实原图。`final-product-{1440/768/390}.png` |
| 首轮接入全景后镜头集中在地板，仍难辨认空间 | 背景采用独立 68° 广角取景，校正方向，清楚呈现窗框、墙和地面；产品保持原来的近景构图。`first-product-1440.png` 记录修正前，`final-product-1440.png` 记录修正后 |
| 庭院总览看不清叶片、枝干与水面 | 增加水景/植物近景，使用当前模型与材质；叶片平面加入弯曲和重算的法线。`final-garden-{water/plant}-{1440/768/390}.png` |
| 水景近景在手机上让树冠进入长标题区域 | 近景使用对应的短标题，减少副文案；状态文字加入底板。检查 `final-garden-water-390.png`，标题与工具栏保持可读 |
| 展开原图可能改变展示高度与相机 | 固定产品展示高度；实际检查展开前后 Canvas 高度相同。庭院原有固定高度也保留 |
| 全景失败或设备没有 WebGL 时可能误称完整效果 | 全景失败明确显示棚拍回退；二维模式关闭室内、反射及水景/植物相机，保留参数和导出 |

截图是本地浏览器的实际运行画面，录像为 `assets/business-scenes-v6.mp4`，没有生成 UI 截图。`scene-refinements-v6-gallery.png` 仅将实际舞台截图缩放排列。品牌素材和其交互本轮沿用第五版。

新增 41 项检查核对解码素材、实际像素、状态同步、需求单与 PNG/JSON、三种视口和失败/兼容状态，见 `scene-refinements-v6-verification.json`。品牌/庭院的 41 项回归、产品 50 项及技能 39 项也已通过。原业务回归结果另见 `verification.json`。检查覆盖浏览器视口，没有真实手机 GPU 或屏幕阅读器验证。

房间为生成的 LDR 全景，背景与产品使用不同取景镜头；它不是可行走的真实三维房间，未校准摄影透视或照度。叶片纹理、模型与水面用于交互概念呈现。功能和截图核对不能证明与原站影像质感相同，最终视觉偏好由用户判断。
