用户只需要给出产品与访客任务，可补充受众、优先项、偏好和已有资料。系统提供通用质量要求，方案层组织本产品的素材、构图、材质、交互与可观察验收。没有把马桶的坑距标准复制到耳机。

耳机案例的输入为看清外观、比较材质、选择配色并留下配置。预置方案是本次代理模型在制作时制定的结果，页面明确标示“AI 制作示例 · 预置”；点击按钮不会把示例重新变成一次在线调用。输入修改后停用旧方案并切换到本地规则草案。在线要求服务已实现，但本机未配置密钥，没有付费或真实模型调用。

## 实际页面与素材

原创 AURA 系列采用暖象牙色摄影空间、雾银椭圆金属外壳、深色耳垫、连续头梁和细小控制件。使用 built-in ImageGen 制作横版主视觉、独立竖版与同系列近景，三项资产存放在 `web/foundry/assets/headphone-*-v12.webp`；来源、尺寸与生成要求见 [素材记录](headphone-assets-v12.json)。固定影像负责系列表达，不是实时配置截图。

实时区为本项目参数化 WebGL 模型。实际生成椭圆壳体、耳垫、头梁、支架、旋钮与接口；配色、表面、折叠、部件展开、五个视角及棚拍/夜色照明改变实际模型。用户通过拖动、滚轮或键盘观察，选择与记录来自同一状态。

图像和几何保持系列设计语言，不能当作厂商 CAD、实拍或工业装配证明。重量、续航、连接与降噪性能保留未知；没有音频试听、正式报价或订单。

## 要求生成与执行的边界

- `planning-contract.js`：封闭方案结构、输入边界与产品分类。
- `planner.js`：本地规则、预置示例及在线传输；本地规则不保证理解任意自然语言。
- `studio.js`：输入、来源、过期取消、下载方案与载入已有产品模块。
- `planning-server.py`：服务端凭据、Responses API 结构化输出、格式/类别校验及可理解的错误。
- `headphone-domain.js`、`headphone-renderer.js`、`headphone-preview.js`：耳机自己的状态、形体、视觉与消费者任务。

方案进入工作台时携带目标、受众、标题、说明与制作要求。当前适配器不会自动按任意方案改写素材、镜头或代码；未覆盖要求仍需实际制作与复核。陌生产品和入耳式耳机归为 `other`，可以下载制作清单，不能打开头戴耳机模块冒充已完成。

## 验证结果

[43 项完整路径检查](headphone-verification-v12.json)通过，无主流程浏览器错误。检查包括来源、修改输入后的失效、本地目标变化、陌生类别、文本安全、真实材质/折叠/展开/环境像素变化、配置/Markdown/PNG、相机与选配恢复、保存/导入、操作范围关闭、1440/768/390 布局和 WebGL 降级。

PNG 与实际画布逐字节一致；手机画布滚出视口后仍导出最新像素。实际下载的 [独立包](headphone-downloads-v12/idea-foundry-headphones.zip)经完整性和路径检查，在阻断包外资源的隔离来源运行，恢复真实颜色、65% 折叠、夜色与自定义观察角度，并继续操作。该包保留验证时的选择，主视觉仍为固定系列意象。另提供 [默认完整案例包](headphone-downloads-v12/idea-foundry-headphones-showcase-v12.zip)，使用默认银色、0% 折叠与暖棚；最终画面与错误状态复核见 [独立交付报告](headphone-final-delivery-v12.json)。

在线接口的成功、失败和取消使用浏览器模拟传输；Python 的 12 项测试覆盖请求契约、缺密钥时不调用网络、拒绝、未完成、错误 JSON/结构/类别/配色、超时释放与并发限制。它们证明接线和错误处理，不能证明真实服务的可用性、费用或生成质量。

共同底座回归 44 项、马桶回归 49 项、静态站 6 项、17 项项目清单与项目内技能格式校验通过。复现脚本在 `tooling/verify-headphone-v12.mjs` 和 `tooling/test_planning_service.py`。视觉证据另见 [设计核对](../design-qa.md)，功能数量不用于证明与原站审美水平相等。

当前价值是减少用户编写技术细节的负担、保留清楚的制作依据，并让团队核对实际交付。真实用户是否更容易理解、选配是否更快，以及商业效果仍需测量。
