# 保存与扩展的能力对应

2026-10-03，用户要求先保存当前能力，再基于它扩展场景构建和骑马探索；随后要求“继续补全”，019 v2 延续这套场景补充路线指引、地点停留、恢复骑行与可选声音。

018 是保存的直接基础，019 是独立扩展。018 的代码与公开资源在此次扩展中保持原样。基线 ZIP 同时保存源码、客户端和许可，SHA-256 清单用于核对，不依赖未来 npm 包的解析结果来重建已经保存的网页。

| 能力层 | 保存的 018 | 019 扩展 |
| --- | --- | --- |
| 场景构建 | 山脊、主路、草坡、林簇与雪峰 | 连通谷侧与山肩支线、溪流、营地、观景台 |
| 角色 | 奔跑形变马、联动骑手、披肩与接触阴影 | 用户控制行进、转向与速度，动画按实际移动调整 |
| 探索 | 沿固定路线观看风景 | 世界坐标地图、地点发现；v2 沿真实小径导航、返路提示及每地点停留 12 秒 |
| 镜头 | 跟随、首次拖动接管、环绕与滚轮 | 自由骑行中的跟随和摄影；v2 在附近地点打开卡片并取景，保持马匹实际位置 |
| 大气 | 三种天气、谷雾、距离雾、风和透光 | 在新地点保留这些控制和实时变化 |
| 记录 | 暂停、重置、沉浸、原始 PNG | 地点发现与取景输出；v2 保存位置、路程、世界时刻、天气及取景参数，点击后继续骑行 |
| 声音 | 原版静音 | v2 默认关闭的程序风声、近处溪流与火堆、随真实移动距离触发的三拍蹄声 |

新地点是同一个实时三维世界中的几何与资源，不是把原视频截帧贴成场景背景。地图与支线采用同一份数据，避免路线显示与实际位置分离。

v2 的路线按小径连通关系计算，地图显示沿路路径、距离和转向，离路时先提示回路。巡游在三个地点中心 2 米范围内停留 12 秒，可点击“继续巡游”提前出发。`E` 打开附近地点卡，“在此取景”只调整镜头；摄影冻结骑行和世界时间。

浏览器保存最近有效骑行，但页面每次仍从默认起点打开，用户点击“继续上次骑行”才恢复；马匹以静止自由骑行继续，存档不会自动开启声音。环境声由 Web Audio 合成，无外部录音；按实际距离衰减和触发，暂停、摄影或页面隐藏时静音。

v1 的 25 项场景检查与当时客户端散列保留在历史记录中。本轮 v2 已通过 43 项自动检查，最终构建和浏览器证据由 `notes/build-validation-v2.json` 与 `design-qa.md` 的 v2 记录补充；不将 v1 截图或散列作为 v2 的最终验收。

保存的能力不等于完整游戏底座：原马动画、有限区域、简化地形约束与浏览器图形性能仍决定实际边界。已有视觉表现应与本轮扩展的实际截图分别核对。
