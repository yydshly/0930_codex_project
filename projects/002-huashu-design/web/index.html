HOW IT WORKS

浏览器，是共同的画布。

规则让 Agent 决定怎么做，代码把设计表达出来，浏览器生成可见结果，转换工具负责交付。这里没有新的模型训练过程。

完整工作流与中间产物

动画为什么可以逐帧渲染？

把画面表示为 frame = render(time)。渲染器依次传入 0、1/60、2/60 秒，取得每帧画面。位置、大小、透明度必须由这个时间决定，独立运行的动画需要适配。

拖动时间轴体验

PPT 为什么不能无损转换？

网页使用流式布局，PPT 使用固定坐标对象。转换器可以测出当前页面的位置，但必须重新表达字体、段落和形状。SVG 或复杂视觉可能成为图片，交互也不会随之保留。

比较交付路线
文档约束与程序约束不同

“先确认方向”“不要使用某种视觉套路”主要由模型执行。截图脚本、错误退出、可选渲染 hook 等才是程序层检查。存在指令，不等于每次执行都能遵守。

按实际素材修改后使用

一次有意义的试用

  1. 选一份你已完成过、能够判断好坏的真实材料。
  2. 固定模型、素材与任务范围，记录初稿和修改过程。
  3. 分别统计准备、生成、修改、导出和验收耗时。
  4. 检查内容错误、返工次数、编辑能力和目标格式兼容性。
  5. 把你认可的规范保存下来，再换一项任务测试是否有效。

需要用户反馈、服务接口、多人协作或长期上线时，把这些工作作为独立工程评估。

数据流与成本

本地部分

已准备好的 HTML 可本地渲染；格式转换、音频混合与技术校验主要依赖本地工具。若页面引用远程字体或脚本，仍会请求网络。

外部部分

宿主模型的推理、素材查找、依赖下载及可选 TTS/AI 看片涉及外部服务。后两者在脚本里有显式同意门，分别上传文本与视频片段。

成本应计入模型调用、并行方向探索、素材服务、配音/评审、渲染资源以及人工修改。MIT 许可不等于外部 API 或所有素材免费。
